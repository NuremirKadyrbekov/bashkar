# Результаты испытаний прототипа на Windows 11

Дата по журналам: 21 октября 2026 г. Источник: вывод PowerShell и журналов, предоставленный пользователем. Модель ноутбука, точная сборка ОС и объём памяти не зафиксированы.

- Первая версия установщика: ошибка доступа к node.exe; в выводе icacls файла не было видимых записей. Фактическая причина не подтверждена окончательно; во второй версии порядок установки ACL изменён.
- Версия 2: создана тестовая база, служба установлена. В выводе ACL node.exe видны унаследованные разрешения SYSTEM и Administrators на полный доступ, LocalService на чтение и запуск. Доступ обычного пользователя не проверен.
- Запуск службы, статус Running, ответ live — подтверждены выводом пользователя.
- Штатная остановка: Stopped, отсутствие server.lock, событие stopped в журнале; повторный запуск и NEEDS_ACTIVATION — подтверждены.
- После перезагрузки Windows: Running и live; ready = 503 / NEEDS_ACTIVATION — подтверждены.
- После выхода из Windows и повторного входа: Running и live — подтверждены; проверка без входа пользователя не выполнялась.
- Запрет второго экземпляра: пользователь сообщил, что проверка прошла; вывод проверки не предоставлен.
- Принудительное завершение node: live недоступен, lock остался, служба сначала показывала Running, позже Stopped. Процессы node/wrapper по предоставленному фильтру отсутствовали; автоматического восстановления не наблюдалось.
- После проверки отсутствия процессов и ручного переноса lock в журнал: служба запущена, live отвечает, ready = 503 / NEEDS_ACTIVATION. Это не проверка восстановления финансовых данных.

Не проверены: доступ и действия стандартного пользователя, полное дерево ACL, точные свойства оборудования, Windows 10, тест с реальным Desktop, автономные бизнес-операции, сбой питания/целостность данных, восстановление базы, печать, сетевые устройства и облако, управляемый автоматический рестарт. Не считать службу или этап 1 принятыми.

## Изолированный эксперимент с блокировкой SQLite

Пользователь запустил `prototype/verify.cjs` из пакета `bashkar-os-lock-test.zip` на том же ноутбуке Windows 11. По предоставленному выводу все три проверки PASS: один владелец из шести конкурентов; повторный захват после принудительного завершения; повторный захват после штатного освобождения. Тест использовал временный отдельный файл и не взаимодействовал с установленной службой и её базой.

Результат подтверждает только данный эксперимент на данном ноутбуке. Совместимость старого и нового прототипа службы, альтернативные пути к файлу, удаление/подмена файла, защита каталога, блокировка в LocalService, сбои ОС/питания, политика перезапуска SCM и Windows 10 не проверены.
