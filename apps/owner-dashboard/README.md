# Bashkar Owner Dashboard

Статический сайт владельца в `dist/`: обзор, продажи блюд, закрытые отчёты смен, журнал продаж и вклад сотрудников выбранной смены. Вход через подтверждённый Supabase Auth; токен хранится только в памяти вкладки. Все RPC чтения проверяют принадлежность организации владельцу. История смен и журнала загружается страницами по 30 записей.

Источники: локальные подтверждённые операции → подписанная фоновая синхронизация → частные таблицы Cloud → RPC агрегатов и истории. Пустой Cloud не подменяется демонстрационными числами; сайт показывает время последнего полученного факта. Рабочая касса и закрытие смены не ждут Cloud. Локальные очереди переживают перезапуск и повторяют доставку.

Для запуска в Cloud требуется последовательно применить миграции `20261103000100`–`20261103000600`, развернуть обновлённую Edge Function `menu-sync`, обновить локальный сервер до схемы 26, проверить обратную загрузку и только затем опубликовать `dist/`. Проверка интерфейса: `node apps/owner-dashboard/test/qa.cjs`; она перехватывает Cloud запросы и не создаёт реальные продажи.

Telegram: принятие отчёта создаёт одно логическое задание. Привязка получателя и отправка ботом ещё не реализованы. Сайт показывает `WAITING_CONFIGURATION`; он не сообщает, что сообщение отправлено.

Текущие ограничения: сайт не видит локальную очередь, если компьютер филиала выключен; он показывает лишь время последнего принятого Cloud факта. Сверка сумм между отчётом смены, журналом и аналитическими фактами пока не автоматизирована. Исправление ошибочного способа оплаты в POS пока не предусмотрено.
