## 1. Цель и границы

Привести публичный сайт меню к приложенному HTML-макету: шапка с брендом и переключателем языков, широкий стартовый баннер, поиск, горизонтальные категории, заголовок каталога, сетка карточек, окно деталей блюда и подвал. Сохранить адаптивность для телефона и маршруты `/b/{branchId}` и `/b/{branchId}/t/{tableCode}`. Внешний вид должен быть близок к макету по компоновке, типографике, отступам, скруглениям и поведению на размерах экрана, заданных в HTML.

Источник блюд, категорий, цен, вариантов, переводов и фотографий — действующая публичная проекция подтверждённого каталога филиала. Демонстрационные ARÇA, девять блюд, эмодзи, цены, «Хит»/«Новинка», внешние URL изображений и фраза «ДЕМО МЕНЮ» из HTML в рабочие данные не переносятся. Если для элемента нет данных в каталоге, показывается нейтральное состояние или элемент скрывается. Оформление не добавляет корзину, заказ или оплату.

## 2. Вкладка Desktop «Публичное меню»

В экране **Меню** добавить вкладку **«Публичное меню» сразу после «Категории»**. В ней показывать настройки текущего филиала, состояние публикации, время последнего обновления, ссылку на сайт и кнопку открытия предпросмотра. Действующий Owner-переключатель «Показывать меню на сайте» перенести сюда из диалога «Меню и Cloud», сохранив его прежнюю серверную проверку. Если ссылка ещё не настроена или Cloud недоступен, показать конкретную причину и не создавать ложную рабочую ссылку.

Вкладка доступна для просмотра сотруднику с доступом к экрану меню; изменение оформления, загрузка изображений и включение/выключение сайта на первом этапе доступны **Owner**. Для остальных поля и действия публикации недоступны. Переключение вкладок предупреждает о несохранённых правках; черновик оформления не смешивается с черновиком каталога.

### Поля

| Блок | Что можно настроить | Правило показа |
|---|---|---|
| Бренд | Логотип ресторана; при отсутствии — монограмма из названия филиала. Название филиала берётся из существующего источника и не дублируется в настройках оформления. | Логотип в шапке сайта; корректный `alt` с названием ресторана. |
| Стартовый баннер | Фоновое изображение с заменой и удалением; фокус кадрирования для разных ширин; верхняя метка, крупный заголовок, описание и нижняя строка. | Текст поверх читаемого затемнения; при отсутствии изображения — фон выбранной темы. Код стола выводится отдельной подписью, если маршрут относится к столу. |
| Заголовок каталога | Заголовок и короткое описание секции блюд. | Значения по умолчанию локализованы; пустое описание скрывается. |
| Языки сайта | Какие языки из языков **опубликованного каталога** доступны посетителю и какой открывается по умолчанию. | Переключатель показывает только выбранные языки. Переводы блюд берутся из каталога с существующим fallback на основной язык. Добавление языка здесь не создаёт переводы блюд. |
| Цветовая тема | Готовые варианты **«Изумрудная»** (палитра макета), **«Светлая»**, **«Тёплая»** с миниатюрами. | Меняются только цветовые токены: фон, текст, кнопки, границы, акцент, баннер и карточки. Порядок и структура блоков одинаковы. |

Тексты баннера и заголовка каталога вводятся **отдельно для каждого включённого языка**. Для незаполненного перевода используется текст основного языка; пустое основное поле, обязательное для заголовка, не публикуется. Поддержать кириллицу и латиницу. Системные подписи поиска, пустого состояния, деталей блюда и подвала локализуются в коде сайта для поддерживаемых языков; в настройках первого этапа они не редактируются.

### Работа с настройками

Кнопки: **«Предпросмотр»**, **«Сохранить и опубликовать оформление»**, **«Отменить правки»**. Предпросмотр показывает текущий черновик на реальных публичных данных филиала, не открывая его гостям; если каталог ещё не опубликован, показывает пустой каталог с явной пометкой предпросмотра. После сохранения новые настройки видны на маршрутах филиала и всех его столов. Изменение темы или текста не требует новой публикации каталога. Отключённый сайт остаётся недоступен гостям, но настройки сохраняются и доступны в Desktop.

## 3. Данные, файлы и API

- Хранить настройки оформления **по `branchId`** отдельно от версии каталога и отдельно от черновиков меню. Предусмотреть ревизию/время обновления и сравнение ожидаемой ревизии при сохранении: одновременные изменения двух Owner не должны молча затирать друг друга.
- Логотип и изображение баннера загружать через Cloud media-поток по образцу фотографий блюд: проверка Owner и филиала, валидация типа/размера, оптимизация и хранение файлов в Bunny Storage; в Cloud-БД хранить только связи и метаданные. Local Server не хранит байты. Замена получает новый путь/ревизию для обновления кеша. Удаление возвращает оформление по умолчанию.
- Для изображений принять JPEG, PNG и WebP; ограничение исходника **10 МБ**. При подготовке выдачи нормализовать ориентацию и оптимизировать размер. Баннер должен иметь подходящее разрешение для широкого экрана; Desktop показывает предупреждение о слишком маленьком изображении и область кадрирования. Логотип сохраняет пропорции и не обрезается.
- Публичный `public-menu` API расширить только безопасными полями оформления: локализованные тексты, ID темы, публичные URL файлов, выбранные языки и ревизия оформления. Не выдавать черновики, внутренние пути хранения, права, токены или служебные ключи. Проверка `enabled` и проверка стола сохраняются.
- Отдельный Owner API для чтения/сохранения настроек и выдачи разрешения на загрузку файлов. Ошибки сохранения/загрузки должны быть видны в Desktop; до успешного подтверждения старое опубликованное оформление остаётся на сайте.
- Настройки отсутствующего филиала получают тему макета, текстовые значения по умолчанию и доступные языки каталога. Миграция существующих филиалов не меняет их каталог или признак публикации.

## 4. Поведение сайта по макету

- Шапка: логотип или монограмма, название филиала, переключатель языков. Демонстрационную плашку не выводить на рабочем сайте.
- Баннер: выбранная фотография и цветовое затемнение с достаточной контрастностью текста; без фотографии — градиент выбранной темы. Декоративное эмодзи из демо не является контентом рабочего сайта.
- Поиск фильтрует реальные опубликованные блюда по названию на текущем языке с существующим fallback. Категории строятся из реального каталога. «Популярное» выводить только при появлении достоверного признака популярности; на этом этапе не добавлять фиктивную категорию. Количество блюд отражает текущую выборку.
- Карточка: фото из текущего Cloud-манифеста либо нейтральная заглушка; переведённые название/описание, корректная цена в сомах. Не показывать «Хит», «Новинка», вес или состав без соответствующих полей данных.
- Окно блюда сохраняет существующий корректный выбор вариантов, модификаторов и матричных комбинаций и точный расчёт цены. Демонстрационную кнопку действия заменить на информационное состояние «Для заказа обратитесь к официанту»; она не обещает отправку заказа. При наличии столового маршрута показывать подтверждённый сервером стол без данных посещения.
- Сохранить состояния загрузки, пустого меню, отсутствия результатов, ошибки сети, выключенного меню и недоступного стола. Сайт работает с клавиатурой, имеет видимый фокус и корректные подписи элементов. На телефоне окно блюда удобно закрывается и прокручивается; блоки не выходят за ширину экрана.

## 5. Приёмка

1. На ширине 1440 px сайт повторяет приложенный макет по структуре и общему визуальному ритму; на 390 px использует мобильное поведение из HTML. Проверить также промежуточную ширину и длинные названия на RU/KY/EN.
2. После «Категории» видна вкладка «Публичное меню». Owner меняет баннер, логотип, тексты, языки и тему, видит предпросмотр и публикует. Другой сотрудник не может изменить данные ни через UI, ни прямым API-запросом.
3. Новое оформление появляется на `/b/{branchId}` и `/b/{branchId}/t/{tableCode}` без перепубликации каталога; у другого филиала оформление не меняется. Изменения каталога не сбрасывают оформление.
4. Проверить замену/удаление изображений, обновление кеша, отсутствие изображения, недопустимый файл, конфликт ревизий, ошибку Cloud и незаполненный обязательный заголовок. Ошибка не приводит к частично опубликованным настройкам.
5. Все реальные данные каталога остаются верными: категории, переводы, описания, фото, варианты, модификаторы, матричные цены, точность тыйынов и отсутствие служебных товаров. Проверить выключенный филиал и недоступный стол.
6. В опубликованном HTML/API нет данных демо, приватных полей и секретов. Изображения выдают только публичные файлы своего филиала.
