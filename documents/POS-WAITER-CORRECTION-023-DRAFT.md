# POS-WAITER-CORRECTION-023 — принятые блюда: выдача, действия и частичная отмена

**Статус:** реализовано 29.10.2026 после подтверждения. Область: POS Desktop «Заказы сначала», Waiter Web «Активный стол», Local POS Server только в части безопасного подключения уже существующих операций.

## 1. Текущая основа

- В кассе уже есть счётчик выданного количества, серверный `order.fulfillment.mark` с CAS и записью фактического исполнителя. В Waiter Web пока нет маршрута для этого действия.
- Сервер уже поддерживает `CANCEL_QUANTITY`, `GROUP_CANCEL`, `CHANGE_COMMENT`, `CANCEL_ORDER`, подтверждение актуальной ревизии и отзыв прав. Отмена уменьшает сумму, сохраняет историю и создаёт кухонное задание `purpose=CANCEL` для кухонных блюд. Физический результат печати не гарантируется сохранением заказа.
- Текущий шаблон кухонного чека показывает положительное количество рядом с заголовком «ОТМЕНА». Формат `−2` — отдельная задача для шаблона печати; не менять транспорт и настройки принтеров в рамках этого ТЗ.

## 2. Карточка принятого блюда в кассе

В режиме «Заказы сначала» убрать отдельную красную кнопку удаления с каждой принятой карточки. Оставить название, вариант/комментарий, действующее количество и стоимость, существующий счётчик выдачи `выдано / действует` с кнопками `− / +`, а также кнопку `•••`. Счётчик выдачи меняет только факт выдачи, не количество заказа и не сумму. У отменённой полностью позиции оставить историческую строку без доступных действий.

`•••` открывает небольшой popover, привязанный к карточке, с двумя кнопками-иконками:

1. `×` — «Отменить количество».
2. Иконка комментария — «Изменить комментарий».

Действие «Заменить блюдо» из этого popover убрать. Всплывающее меню закрывается по выбору, клику снаружи, Escape и смене экрана; не выходит за края окна. Иконки имеют понятные `aria-label` и подсказки. Если у сотрудника нет `order.correct`, меню корректировки недоступно.

## 3. Модальное окно частичной отмены

После выбора `×` открыть компактное оформленное окно в стиле Bashkar. Показать блюдо, вариант, действующее количество, цену за единицу и текущую сумму строки. Счётчик `− / число / +` выбирает, сколько отменить: целое от **1** до фактически действующего количества, начальное значение **1**. При изменении показывать сумму уменьшения; окончательную сумму заказа брать только из серверного `prepare`.

Причина обязательна. Под полем — быстрые варианты «Гость передумал», «Добавлено по ошибке», «Блюдо недоступно», «Другое». Нажатие заполняет редактируемое поле; сотрудник может уточнить текст. «Другое» переводит фокус в поле. Кнопки: «Назад» и «Проверить отмену»; после серверного расчёта в том же окне показать точное количество, сумму уменьшения и новую сумму заказа, затем «Подтвердить отмену». Если отменяется последняя действующая позиция, явно предупредить о закрытии заказа/освобождении стола и потребовать `order.cancel` дополнительно к `order.correct`.

При нескольких действующих порциях одного Order Item выбранное количество распределять по серверным `portionId` в устойчивом порядке, без отмены сверх остатка. Отправлять `CANCEL_QUANTITY` для одной порции либо `GROUP_CANCEL` для нескольких; использовать текущие ревизии, `confirmationHash`, `commandId`, серверные разрешения и существующее восстановление неопределённого результата. После успеха перечитать заказ, сумму, выдачу и историю. При конфликте, оплате, отзыве права или недоступности Local POS Server показать ошибку и не считать отмену принятой.

## 4. Изменение комментария

Иконка комментария открывает окно с действующим текстом. При нескольких порциях с разными комментариями сотрудник сначала выбирает конкретную порцию и количество. Сохранение идёт через существующие `CHANGE_COMMENT` prepare/commit и разрешение `order.correct`. Для `CUSTOM_AMOUNT` действие скрыто: сервер запрещает комментарий к такой позиции. «Заменить блюдо» из интерфейса принятой карточки убрать; серверный контракт замены в этом ТЗ не удалять.

## 5. Waiter Web

У принятой позиции сделать те же элементы и порядок: данные блюда, счётчик выдачи, `•••` с двумя иконками, общие правила частичной отмены и изменения комментария. Убрать отдельный красный `×` рядом со строкой. Сохранять мобильную ширину от 320 px, размер касания от 44 px, отсутствие зума при вводе, русскую и кыргызскую подписи.

Для счётчика выдачи добавить только защищённый TABLE-маршрут Waiter Web к существующему серверному `FulfillmentService.mark`. Проверять `order.fulfillment.mark`, доступ к посещению в STRICT/SHARED, текущую ревизию и идентификатор команды. Значение показывать как `выдано / действует`; выдача не меняет стоимость и не создаёт кухонное задание. При отмене сервер ограничивает выданное количество новым действующим остатком по существующему правилу.

## 6. Кухонная печать и граница задачи

Не создавать новый механизм печати, не менять драйверы, очередь и настройки. При подтверждённой отмене сохранить существующее серверное задание `CANCEL` с точным **положительным** количеством отменённых единиц, блюдом, вариантом, столом, причиной и исполнителем. Для будущего отображения `−N` шаблон печати должен преобразовывать знак только при `purpose=CANCEL`; числовое количество в истории и API остаётся положительным. Текущий сервер может отправить уже существующее задание на настроенную кухню; обещать «печать не происходит» нельзя. Отдельно проверить формат `−N` и физическую доставку на Windows/принтере при следующем этапе печати.

## 7. Приёмка

Проверить для кассы и Waiter Web: отсутствие красной кнопки, счётчик выдачи, popover из двух действий, комментарий, отмену 1 из 3 и 2 из 3, несколько порций одного блюда, последнюю позицию, сумму со скидкой/сборами, неизменность исходного Batch/Item, кухонное задание `CANCEL` с количеством 2, STRICT/SHARED, запрет после оплаты, отзыв права, конкурирующую коррекцию и потерянный ответ. Экранные проверки — 1366×768/1920×1080 для POS и 320/390 px для Waiter Web. Рабочий профиль MANGO не изменять автоматически; использовать изолированный тестовый профиль. Физическую печать не объявлять проверенной без теста на оборудовании.

## 8. Результат реализации и проверок

- POS: отдельная красная кнопка удалена. `•••` показывает иконки отмены и комментария. Модальное окно отмены содержит счётчик, причину, быстрые варианты и серверный расчёт перед подтверждением. Действие замены из карточки убрано.
- Waiter Web: принятые позиции показывают актуальный остаток и комментарии при сохранении исходного снимка пакета. Добавлены счётчик выдачи через защищённый TABLE-маршрут и тот же popover с частичной отменой. Убрана старая коррекция с заменой из верхнего меню.
- Проверены `pnpm run check` и `pnpm test` (40 файлов, 238 тестов), изолированный Desktop QA (отмена 1 + 2 единиц, два задания `CANCEL` с количеством 1 и 2, неизменный Batch, закрытие стола, 1366/1920) и Waiter HTTP QA (выдача, комментарий, отмена, 320/390). Тесты использовали только одноразовые профили.
- Отображение `−N` на кухонной бумаге и физическая доставка на принтер остаются отдельной задачей печати. Сервер сохраняет положительное количество и `purpose=CANCEL`; рабочий шаблон пока печатает положительное количество под заголовком «ОТМЕНА».
