## Права и область доступа

Все маршруты используют текущую локальную сессию, готовый активированный филиал и существующий защищённый loopback API. Клиент не выбирает branch/actor/role; неизвестные поля тела отклоняются. Первая смена временного пароля, блокировка/архив, отзыв сессии/права применяются также к replay.

| Право | По умолчанию | Область |
|---|---|---|
| `table.view_status` | Owner, Manager, Cashier, Waiter | Карточки активных столов своего филиала |
| `table.view_details` | Те же | Дополнительно проверяется доступ к посещению |
| `table.open` | Те же | Активные стол/зона/смена и явно настроенный режим |
| `table.close_empty` | Те же | Доступное посещение, revision, отсутствие принятых пакетов/платежей |
| `table.access_others` | Ни у кого | Явное отдельное предоставление по существующим ограничениям управления правами |
| `table.manage` | Owner | Manager — только по grant; Cashier/Waiter не разрешено |
| `settings.table_access_mode.manage` | Owner | Manager — только по grant; Cashier/Waiter не разрешено |

STRICT разрешает свои посещения по responsible_waiter_id; для неофицианта без назначенного официанта — собственное opened_by. SHARED открывает совместный доступ к OPEN-посещениям при наличии права операции. `table.access_others` даёт доступ к чужим посещениям, включая историю. Автоматического обхода для Owner нет. Ответственный не меняется при смене режима.

В закрытых посещениях SHARED сам по себе не даёт доступ к чужой истории. Список чужих столов содержит только конфигурацию, FREE/OCCUPIED, sessionId, isMine/canViewDetails; имена исполнителей, время и подробности посещения возвращаются только разрешённым GET details.

## Маршруты

Пути относительно `/api/v1`, токен в существующем заголовке Authorization. POST дополнительно содержит UUIDv4 `commandId`.

| Метод / путь | Данные | Результат |
|---|---|---|
| GET `/tables` | — | settings {mode,revision,configured}, zones[], tables[] с состоянием/доступом |
| GET `/tables/waiters` | — | id/name действующих официантов; Waiter видит только себя |
| GET `/tables/visits/:id` | UUID посещения | Снимки стола/зоны/исполнителей, shiftId, время, статус, revision и защитные признаки |
| POST `/tables/zones/save` | zoneId null или UUID, revision, name, active | Конфигурация зоны |
| POST `/tables/save` | tableId null или UUID, zoneId, revision, name, active | Конфигурация стола |
| POST `/tables/settings` | revision, mode STRICT/SHARED | Новые настройки режима |
| POST `/tables/open` | tableId, responsibleWaiterId null или UUID | sessionId, tableId, state OCCUPIED, revision 1 |
| POST `/tables/close-empty` | sessionId, revision | sessionId, tableId, status CLOSED, closeReason EMPTY, новая revision |

Новая конфигурация передаётся с revision 0; существующая — с последней revision. Названия: непустые до 200 символов, NFKC, свёртка пробелов, регистронезависимый ключ. Уникальны внутри филиала, включая отключённые записи. Нет физического удаления/переиспользования старого имени. Занятый стол нельзя переименовать, перенести или отключить; занятую зону нельзя изменить. Зона отключается только без активных столов. Активный стол требует активную зону.

До явного сохранения режима отображается STRICT как предложение; открыть посещение нельзя. Смена режима действует на следующие команды и существующие OPEN-посещения, не переписывая историю. В UI есть подтверждение. CAS-конфликт требует обновления данных.

Официант при открытии всегда становится ответственным сам (подмена другого запрещена). Неофициант выбирает действующего официанта; null допускается только при отсутствии активных официантов. opened_by всегда реальный исполнитель. Снимки имён/названий сохраняются при открытии и не редактируются. Переназначения в MVP нет.

## Транзакции и ошибки

Все POST используют существующий сериализованный CommandBus: бизнес-данные, audit, outbox и результат фиксируются в одной транзакции. Повтор того же ID с теми же actor/type/семантическим payload возвращает прежний результат после проверки текущего доступа. Иной payload конфликтует. Результаты открытия/закрытия минимальны и не содержат частных снимков, которые могли бы утечь через replay.

Один OPEN на стол обеспечивает частичный UNIQUE в SQLite. При гонке новый ID проигравшего получает `TABLE_OCCUPIED` 409. Потеря ответа означает неизвестный результат: Desktop хранит команду зашифрованно и повторяет прежний ID, включая после рестарта сервера/клиента. Нет оптимистического локального подтверждения открытия.

Основные ошибки: `REVISION_CONFLICT`, `TABLE_OCCUPIED`, `ZONE_OCCUPIED`, `ZONE_HAS_ACTIVE_TABLES`, `ZONE_INACTIVE`, `TABLE_INACTIVE`, `TABLE_NAME_USED`, `ZONE_NAME_USED`, `TABLE_MODE_REQUIRED`, `SHIFT_REQUIRED`, `RESPONSIBLE_WAITER_REQUIRED`, `INVALID_RESPONSIBLE_WAITER`, `VISIT_CLOSED`, `VISIT_NOT_EMPTY` — 409; отсутствие доступа — 403; отсутствующий объект своего филиала — 404; невалидные поля — 400. Ошибки реестра auth/CommandBus сохраняют существующие коды.

## История и будущие зависимости

Закрытие EMPTY требует, чтобы посещение никогда не имело принятого пакета или зарегистрированного платежа. Сейчас настоящих пакетов/платежей нет. `has_accepted_batch` и `has_registered_payment` — монотонные защитные признаки: будущие модули обязаны выставлять их вместе с первым фактом в той же транзакции. Они не являются заменой заказа/платежа и не доказывают готовность финансового контура.

SQL защищает неизменность открывшего/ответственного/снимков/принадлежности, запрещает удаление истории, обнуление защитных признаков, повторное изменение закрытого посещения и закрытие EMPTY с установленным признаком. Каждое изменение посещения увеличивает revision. История закрытия содержит исполнителя, время, причину EMPTY. Новое открытие того же стола создаёт новое посещение.

Формы предупреждают об утрате несохранённых настроек при обновлении/навигации и сохранении другой формы. Состояние обновляется каждые 5 секунд без продления idle-сессии; редактирование и модальные окна приостанавливают перерисовку. Открытая карточка повторно проверяет доступ/версию. Время показывается в Asia/Bishkek.
