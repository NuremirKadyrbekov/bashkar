## Объём этапа

1. Столы и посещения в активной смене; одно активное посещение на стол; отдельные opened_by/responsible_waiter; STRICT/SHARED, без штатной передачи ответственного.
2. Черновик и первый непустой принятый пакет → один TABLE-заказ; дозаказы → новые пакеты того же заказа. Исторические цены/размеры/модификаторы/комментарии/отправитель/редакция/кухонный признак; TABLE-сборы фиксируются первым пакетом.
3. Постоянные задания кухни только для кухонных строк. Весь пакет остаётся в заказе. Business/audit/outbox/job/result атомарны, физическая печать за транзакцией.
4. POS Desktop и отдельный контур Waiter Web. Сетевой выпуск Waiter зависит от D01/D02 и проверки HTTPS/WSS на телефонах/роутере; один Desktop не закрывает весь этап 4.

Оплаты/отмены принятых позиций/COUNTER — следующие этапы. Непустое посещение не закрывается фиктивной оплатой/очисткой; закрытие смены не обходится ради нового экрана.

## Согласованный и реализованный первый UI

**Список столов.** Карточки по зонам, номер/название, свободен/занят; представления «Все» и «Мои». Начать с карточек без редактора геометрического плана зала. В STRICT обычному официанту доступны состояния всех столов, но чужие детали/пакеты скрыты; SHARED сохраняет прежнего ответственного и позволяет операции по правам. Подробности, суммы и состав чужого заказа не возвращаются сервером при отсутствии доступа.

**Настройка.** Реализована небольшая административная форма зон и столов: название зоны, номер/название стола, активность. Owner, Manager — только с отдельно предоставленным правом. Занятые столы и зоны нельзя изменять; отключение зоны требует отключить её столы. Имена уникальны внутри филиала даже для неактивных записей. Контракты и права: `API-TABLES-004.md`. Не создавать демонстрационные столы в рабочем филиале автоматически.

**Открытие посещения.** Нажатие свободного стола → карточка с подтверждением «Открыть стол». Нужны активная смена и серверное право. Для официанта ответственный — он сам. Для кассира/менеджера — выбор действующего официанта по правилам CORE; opened_by остаётся реальным исполнителем. Ответственный не меняется штатной командой MVP.

**Пустое посещение.** Отдельное подтверждение закрытия, причина EMPTY; сервер повторно проверяет отсутствие когда-либо принятого пакета и права. Для непустого посещения такой кнопки обхода нет. Клиентских черновиков в этом подэтапе ещё нет; предупреждение об их потере должно появиться вместе с черновиками.

**Ошибки/связь.** Никакого локального подтверждения занятости до commit. При гонке открытия только одна новая команда успешна; остальные получают актуальное состояние с разрешённым объёмом данных. При потере ответа — прежний command ID; UI блокирует повторный новый запрос того же действия до выяснения исхода. Недоступный сервер блокирует изменения. Обновление состояния не продлевает idle-сессию.

**Рекомендация по первому запуску.** Явная настройка режима Owner при вводе столов; предложить STRICT как исходный выбор, SHARED доступен осознанно. Применение смены режима к следующим командам, включая существующие посещения, без переписи истории. Этот сценарий подтверждён пользователем. До явного сохранения режима открытие заблокировано; автоматической настройки филиала нет.
