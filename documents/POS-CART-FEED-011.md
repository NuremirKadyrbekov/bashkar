# POS-011: единая лента корзины и отправка перед оплатой

Дата: 27.10.2026. Реализовано по подтверждённому ТЗ пользователя и присланному референсу. Область: FAST_FIRST; внутренние пакеты и остальные клиенты сохранены.

## Новый заказ

- Заголовок: «Новый заказ», `⋯`, очистка, неизвестный товар. Под ним — две равные кнопки «Зал / На вынос».
- До принятия первого пакета назначения доступны через native popover `⋯`: стол и официант с текущими значениями. Закрытие — выбор действия, нажатие снаружи, Escape. В режиме выноса пункты недоступны. Открытый popover откладывает фоновые обновления экрана.
- После принятия TABLE под номером заказа показаны стол/ответственный по 50%, ниже — неизменяемый автор. Для COUNTER остаётся тип обслуживания без назначений.
- Кнопка «Зал», назначение стола и выбор стола в FAST_FIRST используют существующую `table-outline.png`.

## Общая лента

- Один прокручиваемый контейнер содержит все принятые позиции по порядку отправки и собираемые позиции снизу. Аккордеона, переключателя истории и отдельной шторки нет.
- Принятые строки имеют мягкий зелёный фон. Между отправками — тонкая линия, подпись «Принято» и серверное время в зоне Asia/Bishkek. Состояние печати показано отдельно.
- Новые строки и разделитель «Новые позиции» жёлтые. При появлении сборки прокрутка переходит к её началу; при добавлении новых строк обеспечивает видимость добавленной. Количество, фоновая перерисовка и просмотр истории не сбрасывают сохранённую позицию.
- История загружается со всех страниц API, включая пакет №21 и последующие. Изменения принятых позиций используют существующие коррекции; отметки выдачи сохраняются.
- Очистка затрагивает только неотправленные строки. При неизвестном результате доступны проверка исходной команды и точный retry; новая отправка/оплата недоступны.

## Футер

- Скидка, сумма новых позиций и общий итог закреплены снизу. Строка «Новый пакет» показана при наличии сборки меньшим шрифтом, над общим итогом.
- Любой непустой новый состав показывает одну кнопку «Отправить заказ». Три способа оплаты скрыты. Это относится и к составу без кухонных блюд.
- После принятия и при отсутствии новых строк появляются «Наличные / Перевод / Смешанная», при нулевом принятом итоге — ZERO. Пустой новый заказ не предлагает отправку или расчёт.
- Обработчики FAST_FIRST также отвергают вызов оплаты с неотправленными строками (`UNSENT_POSITIONS`). Общий серверный атомарный checkout остаётся доступен прежним клиентам и восстановлению старых pending-команд.
- Отправка создаёт существующие кухонные задания только для кухонных строк; принятие не означает физическую печать или готовность блюда.
