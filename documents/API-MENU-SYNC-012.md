## Local API (native POS)

Все маршруты находятся под `/api/v1/menu/sync`. Существующая native-транспортная граница и серверная авторизация сохраняются. Renderer не обращается к Supabase или SQLite.

| Метод / путь | Назначение | Право |
|---|---|---|
| GET `/status` | Фактический локальный/Cloud статус, IDs, очередь, попытки, ACK и причины ожидания | Авторизованный локальный сотрудник |
| POST `/retry` `{}` | Внеочередной фоновый цикл; не публикует форму | menu.edit |
| POST `/lease` `{active,draftId?}` | Короткая блокировка автоприменения, TTL 60 с; открытие черновика переводит его в EDITING | menu.edit |
| GET `/history?before=0` | 20 метаданных Cloud-версий с курсором sequence | menu.edit |
| GET `/versions/:id` | Проверенная полная версия Cloud для просмотра | menu.edit |
| POST `/apply` | commandId, expectedLocalRevision, versionId, preserveDrafts=true; ручное применение совместимого преемника/подтверждённая начальная загрузка | menu.edit |
| POST `/resolve` | commandId, expectedLocalRevision, expectedRemoteVersion, choice=LOCAL/CLOUD, versionId? для восстановления старой | menu.edit |
| POST `/finish-draft` | commandId, draftId; пометить завершённым, сохранив документ | menu.edit |

Опасные операции используют существующий CommandBus/идемпотентный native pending journal. Повтор разрешения конфликта возвращает исходный результат даже после продвижения Cloud head. Фоновые lease/status не продлевают авторизацию сотрудника.

## Cloud Edge

POST `/functions/v1/menu-sync`, `verify_jwt=false`: браузерный bearer JWT не даёт права устройства. Обработчик отказывает при Origin; прямые RPC доступны только service_role в Edge.

1. `challenge`: registrationId → подписанный одноразовый challenge (60 с), branch/instance/device hash. Ограничение выдачи — 120 в минуту на регистрацию.
2. Подписанный устройством запрос включает operation, registrationId/branchId/instanceId, challengeId/nonce, publicKey, body и Ed25519 signature. Proof подписывает protocol=1 и canonical bodyHash.
3. Cloud проверяет ACTIVE registration, владельца организации, hash ключа, подпись, branch/instance. Challenge потребляется отдельной транзакцией **до** бизнес-операции, поэтому ошибка операции не делает proof повторно пригодным.
4. Ответ подписан отдельным menu authority (`menu-v1`), связан с запросом/устройством/филиалом. Local Server проверяет подпись и ID до сохранения данных.

Операции body: manifest, history, version, receipt, push, ack. Push хранит UUID, parent, hash, schema=1, полный normalized catalog, origin, автора, local revision/time и commandId. Same operationId/body возвращает исходный receipt; иное содержимое отвергается. Hash и структурные ограничения проверяются тем же валидатором, собранным из локального catalog.ts (`pnpm run build:menu-cloud`), без отдельной вручную расходящейся бизнес-модели.

Cloud сохраняет конфликтную версию без продвижения head. Отдельный registry владельцев ID запрещает переиспользование ID между типами/родителями/сочетаниями. Согласованный head обновляется CAS по parent; опубликованные верхние сущности сохраняются через архив, а не удаление. Архивирование в Cloud и факт локального применения — разные записи. ACK действует для конкретной регистрации.

## Local worker и данные

- Worker живёт в Local Server; при старте READY проверяет Cloud фоном. Полный цикл каждые 30 с ±10%, после публикации просыпается сразу. Backoff 15/30/60/120/300 с, Retry-After учитывается. Подтверждённый отказ устройства или плохая подпись приостанавливают повторы до ручной проверки.
- Один цикл в полёте. Backfill идёт по существующей истории порциями 8 версий, новые публикации сохраняют UUID/parent/operation ID в той же локальной транзакции. Outbox не дублируется; доставленными помечаются только конкретные menu.published.
- Потерянный ответ выясняется receipt, затем при необходимости повторяется исходная операция с прежним ID. ACK хранится отдельно и повторяется без повторного apply.
- Входящий документ сначала сохраняется как ожидающий. При безопасной линии происхождения, отсутствии локальной очереди/конфликта/активного редактирования/незавершённых черновиков применяется атомарно: документ, указатель, метаданные, scoped системный аудит и pending ACK. Открытая смена не запрещает обновление меню.
- Несохранённые поля renderer не перерисовываются polling-ом. UI сообщает, что серверная редакция сменилась; устаревший base не публикуется поверх новой версии.
- Локальные номера не равны Cloud sequence. Таблица mapping связывает их по UUID и hash. Входящая версия имеет реального исходного автора в metadata, локальный created_by=NULL; фиктивного сотрудника нет. Существующие авторы и документы сохраняются миграцией, история использует LEFT JOIN и provenance.
- Восстановление создаёт новую публикацию. Отсутствующие в выбранном составе более новые опубликованные сущности сохраняются как архивные, актуальные значения доступности/локальный стоп-лист не сбрасываются. Текущие валидаторы ссылок/ID/SET/цен сохраняют силу.
- Синхронизируется только опубликованный каталог. Незавершённые черновики, оперативный стоп-лист, сборы, заказы и деньги в этот поток не включены. Принятые позиции и чеки не пересчитываются.

## Интерфейс

Полоса Cloud в меню, отдельный диалог статуса, внеочередная проверка, Cloud-история и полный просмотр, сравнение локальных и облачных сущностей, выбор состава новой согласованной версии и восстановление старой новой публикацией. Открытый черновик можно явно завершить без удаления. Ручное применение сохраняет документы черновиков и предупреждает об изменении базы.

## Безопасное испытание и включение

`desktop:clean-preview` и обычные fixture не имеют remote transport и никогда не отправляют тестовый ресторан в рабочее Cloud.

- `pnpm test:menu-sync` — SQLite + PostgreSQL/PGlite + настоящий общий Edge-handler, криптография и production SQL/RPC.
- `pnpm test:menu-sync-desktop` — настоящий Electron/Local Server, изолированный PostgreSQL/Edge, без реального Cloud и без отправки локальных секретов наружу.
- `infrastructure/cloud/menu-sync-smoke.cjs` использован для реального end-to-end. Требует явного `BASHKAR_MENU_CLOUD_SMOKE=1` и пути к CLI. До настроенной подписи прекращает работу **до** создания QA-данных. После готовности создаёт отдельные QA-организацию/филиал/устройство, проверяет 60 позиций, историю, потерю ответа, download/apply/ACK, затем отзывает только своё QA-устройство. История сохраняется неизменной. Это тестовый локальный authority, не доказательство новой production-активации.

Ключ установлен пользователем через Supabase Secrets после отдельного подтверждения. В installer/config попадает только public key. Исходный приватный файл никогда не выводится в логи и не включается в артефакты. SQL/Edge развёрнуты; remote end-to-end — **PASS** (24.10.2026).

Миграция SQLite 12 требует штатной процедуры на остановленной проверенной копии. Запрет миграции при открытой смене сохранён. MANGO/существующие локальные базы автоматически не обновлялись. Windows и физические устройства отдельно не проверялись.
