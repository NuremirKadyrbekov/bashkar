# MENU-VARIANT-MATRIX-TECH-001 — обязательные варианты и цены комбинаций

**Статус:** решения 1–5 согласованы пользователем 24.10.2026; реализация и локальные проверки завершены. Приёмка на реальном Windows POS и оборудовании ещё не проводилась. Старых рабочих товаров у пользователя пока нет.

## 1. Цель

В редакторе товара заменить раздельные вкладки «Размеры» и «Модификаторы» одной вкладкой «Варианты и размеры». Владелец задаёт варианты выбора и **полную конечную цену каждой комбинации**, а кассир выбирает ровно один вариант из каждой группы. Система рассчитывает и принимает цену на Local POS Server.

Пример товара «Чай»: группа «Размер» = «Маленькая кружка», «Большая кружка»; группа «Молоко» = «С молоком», «Без молока». Редактор создаёт четыре строки цены. Цена каждой строки задаётся независимо. Это позволяет, например, сделать добавку молока разной для разных размеров без скрытых формул.

## 2. Обнаруженные ограничения текущей версии

- Сейчас `Item.variants` хранит размеры с конечной базовой ценой, `Item.groups[].options` — модификаторы с добавочной ценой; `priceLine()` вычисляет «цена размера/товара + сумма модификаторов». Отдельной цены сочетания нет (`apps/local-server/src/modules/menu/catalog.ts`, `pricing.ts`).
- POS Desktop, Waiter Web и локальный предпросмотр заказа самостоятельно показывают размер и добавку и оценивают цену по старой формуле (`apps/pos-desktop/orders.js`, `apps/waiter-web/app.js`). Простой редизайн редактора дал бы неверные суммы до отправки на сервер.
- Принятые позиции хранят снимок цены и выбора в заказе. Опубликованные редакции и сохранённые черновики уже используют старый контракт. Публикация во время открытой смены допустима.
- CORE-001 §6 определяет добавочную цену модификаторов, а `MENU-OPEN-005` прямо оставляет зависимость цены модификатора от размера неутверждённой. Новое правило требует согласованного дополнения CORE-001.

## 3. Предлагаемая модель MVP

### 3.1. Выбор

1. Необязательная первая группа «Размер»: если она есть, выбирается ровно один размер. Если её нет, у товара одна неявная базовая версия.
2. Ноль или более дополнительных групп, например «Молоко», «Сахар». В каждой группе **ровно один** выбранный вариант. Поля min/max в новом режиме не показываются. Если нужно отсутствие ингредиента, владелец явно добавляет вариант «Без молока» или «Без сахара».
3. Варианты имеют стабильные ID и переводимые названия. Группы относятся к конкретному товару, не образуют глобальный справочник.
4. Цена комбинации — **полная цена одной единицы**, а не прибавка к цене размера/модификатора. Например, четыре цены чая вводятся независимо. Отрицательная цена запрещена; `0` — явная бесплатная цена, пустое поле — ошибка.
5. Если у товара вообще нет групп, редактор показывает одну строку «Базовый вариант» с конечной ценой. Если есть группы, сервер требует цену для каждой допустимой комбинации.
6. Рекомендуемый предел MVP — 64 комбинации на товар. Редактор показывает счётчик до добавления варианта/группы и не даёт превысить предел. Сервер повторяет проверку.

### 3.2. Контракт и совместимость

- Добавить в документ товара явный режим ценообразования. Отсутствие поля означает прежний **legacy additive** режим для существующих опубликованных редакций и черновиков. Новый режим содержит таблицу цен, привязанную к стабильным ID размера и вариантов остальных групп. Ключ комбинации строится по ID, не по видимым названиям или порядку строк.
- Для новых товаров редактор использует матричный режим. Простой товар без групп хранит базовую цену. Старые товары отображаются и рассчитываются по прежним правилам, пока владелец не запустит явное преобразование. Автоматической молчаливой конвертации нет.
- Автоматическая конвертация старого товара не входит в этот MVP, поскольку рабочих товаров пока нет. Старый формат остаётся читаемым и продаваемым для совместимости тестовых и ранее опубликованных редакций; отдельный интерфейс конвертации потребует согласования при появлении реального старого каталога.
- В новом режиме форма заказа сохраняет существующие `itemId`, `variantId` и `modifierIds` для совместимости локальных черновиков, но принимает ровно один ID из каждой группы. Сервер проверяет принадлежность ID товару, уникальность выбора, доступность и существование ровно одной строки цены. `unitPrice` берётся **только** из этой строки.
- В ответе цены и снимке принятого заказа фиксируются выбранные названия/ID, конечная цена, количество и редакция меню. Поля старого снимка не переписываются; рендер печати различает старый и новый режим, не показывает цену комбинации как ложную доплату за «Молоко».
- Существующие `draftSave`, `publish`, проверка базовой редакции, идемпотентные команды и отдельный стоп-лист сохраняются. Прямого доступа Desktop к SQLite нет. Новые поля проверяет сервер на сохранении черновика и публикации.

## 4. Редактор меню

- Одна вкладка «Варианты и размеры» вместо вкладок «Размеры» и «Модификаторы». Остальные вкладки товара сохраняются.
- Первый блок — «Размер». Кнопка добавления размеров; для товара без размеров блок можно оставить пустым. Ниже — «Добавить группу вариантов», название группы и список её вариантов. Для матричного режима группы обязательные, поэтому у каждой должно быть минимум два осмысленных варианта либо один вариант с предупреждением о лишнем шаге для кассира.
- Последний блок — «Цены сочетаний»: строки вида «Маленькая кружка · С молоком — [цена, сом]». Порядок предсказуем: размер → группы в порядке редактора. Если размеров нет, название строки начинается с дополнительных групп. При отсутствии всех групп показывается базовая цена.
- Новая комбинация получает пустую цену. При переименовании/перестановке варианта цена остаётся привязана к его ID. При добавлении новой группы старые строки нельзя безусловно размножать с теми же ценами: редактор показывает предложение копирования и требует явного подтверждения. При удалении группы цены нескольких строк могут слиться; владелец заново выбирает цену результирующей строки. Перед удалением группы/варианта показывается количество затронутых цен и подтверждение.
- Кнопка «Сохранить изменения» фиксирует поля товара в рабочем каталоге. «Сохранить черновик» отправляет целую редакцию серверу. «Опубликовать» публикует проверенный черновик с подтверждением. При переключении товара, закрытии и выходе сохраняются предупреждения о несохранённой форме.
- Для старого товара на той же вкладке ясно показывается прежняя схема «цена размера + доплата». Названия и состояние старых товаров не меняются только из-за открытия редактора.

## 5. Касса и Waiter Web

- Размер выбирается один; каждая дополнительная группа представлена переключателями выбора одного варианта, а не несколькими флажками. Обязательность явно видна.
- До сохранения строки заказа показывается цена именно выбранного сочетания, включая количество. Не разрешать подтверждать неполный выбор или сочетание без цены.
- Desktop и Waiter Web используют одну опубликованную сервером таблицу цен. Клиентский предварительный итог не считается подтверждённым: при отправке Local POS Server заново вычисляет сумму по действующей редакции и требует подтверждения изменившихся условий.
- Сохранённые локальные корзины со старыми ID при смене редакции перепроверяются. Если вариант удалён или цена изменилась, показывается понятная ошибка/новая цена; нельзя молча выбрать другой вариант.
- Печать кухни, клиентский документ, просмотр заказа, корректировки и история показывают выбранные размер и варианты; ранее принятые позиции и их цены неизменны.

## 6. Доступность и ограничения

- Сохраняется отдельный серверный стоп-лист товара, размерного варианта и существующих вариантов дополнительных групп. Недоступный размер или вариант группы исключает все сочетания с ним без публикации новой редакции. Возврат товара не снимает стопы его размеров. Права `menu.edit` и `menu.stoplist.manage` остаются разделёнными.
- **Согласовано:** каждая опубликованная комбинация получает стабильный ID и может быть выключена/включена отдельной существующей серверной командой стоп-листа с CAS-ревизией. Например, «маленький с молоком» отключается, а «большой с молоком» остаётся в продаже. Цена и опубликованная редакция от этого не меняются. Сервер проверяет доступность комбинации при quote и принятии заказа.
- В матричном режиме не поддерживаются необязательные дополнительные группы, выбор двух вариантов из одной группы и цена отдельно взятого модификатора. Старые additive товары продолжают поддерживать прежние min/max, пока не преобразованы.

## 7. Проверки и критерии приёмки

1. Чай с 2 размерами × 2 вариантами молока даёт ровно 4 редактируемые цены. Каждая комбинация рассчитывается и принимается по своей цене, включая случаи, когда разница между «с молоком» и «без» зависит от размера.
2. Пустая ячейка, отрицательная/некорректная сумма, дубликат комбинации, лишний или отсутствующий выбор, несуществующий ID, превышение лимита комбинаций отклоняются сервером. Ноль принимается только при явном вводе.
3. Переименование и перестановка вариантов не меняют цены; добавление/удаление вариантов не теряет введённые цены незатронутых сочетаний. Изменение структуры с неоднозначной новой ценой требует проверки владельцем.
4. Черновик не меняет действующее меню. Публикация атомарна, конфликт базовой редакции не перезаписывается. Открытая смена продолжает работу; старые принятые позиции, коррекции и документы сохраняют прежние суммы.
5. POS Desktop и Waiter Web показывают ту же цену, что серверный quote/accept; местная корзина после публикации новых цен предупреждает перед подтверждением.
6. Стоп-лист варианта действует без публикации всего каталога; отсутствие `menu.stoplist.manage` блокируется сервером. Режим без `menu.edit` не позволяет изменять структуру/цены.
7. Старые каталоги, черновики и заказы читаются без преобразования; старый additive товар можно продавать как раньше.
8. Проверить длинные списки сочетаний, клавиатуру/сенсор, 1366×768 и 1920×1080, локальный сервер offline от интернета и потерю связи с сервером. Новая функция тестируется на изолированной базе, не на MANGO/реальном профиле.

## 8. Утверждённые решения

1. **Новая цена:** считать каждую строку конечной ценой всего сочетания, без дополнительных наценок — рекомендуется.
2. **Обязательность:** в новом режиме ровно один выбор из каждой группы; отсутствие ингредиента оформляется явным вариантом «Без …» — соответствует запросу.
3. **Объём:** максимум 64 сочетания на товар; при превышении редактор предлагает упростить структуру — рекомендуется для MVP.
4. **Старое меню:** рабочих товаров пока нет; сохранять чтение additive каталога для совместимости. Конвертация не требуется в этом релизе.
5. **Недоступность сочетания:** включить отдельный переключатель для каждой комбинации через серверный стоп-лист и право `menu.stoplist.manage`.

Решения подтверждены пользователем. Изменение CORE-001 §6/MENU-OPEN-005 должно явно отличать старый additive формат от нового формата полной цены комбинации.
