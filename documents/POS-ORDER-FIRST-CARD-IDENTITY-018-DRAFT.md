# POS-018 — заголовок и бейджи карточек в режиме «Продажа сначала»

Дата: 29.10.2026. Статус: подтверждено пользователем и реализовано. Область: только карточки активных заказов и отложенных черновиков кассового Desktop в режиме FAST_FIRST («Продажа сначала»). Дополняет [POS-017](POS-ORDER-FIRST-CARDS-017-DRAFT.md).

## Цель

По верхней части карточки сразу понимать, какой это стол или номер заказа, ниже видеть тип обслуживания («Зал» / «На вынос») и отдельный статус («Отправлен» / «Ожидает»).

## Матрица отображения

| Состояние карточки | Заголовок | Под заголовком | Бейдж типа | Бейдж статуса |
|---|---|---|---|---|
| Принятый заказ «Зал», стол назначен | Номер стола, например `С10` | `Заказ №001` | **Зал** | **Отправлен** |
| Принятый заказ «Зал», стол не назначен | `Заказ №001` | Нет повторного номера | **Зал** | **Отправлен** |
| Принятый заказ «На вынос» | `Заказ №002` | Нет повторного номера | **На вынос** | **Отправлен** |
| Ожидающий черновик «Зал», стол назначен | Номер стола, например `С10` | `Заказ №N`¹ | **Зал** | **Ожидает** |
| Ожидающий черновик «Зал», стол не назначен | `Заказ №N`¹ | Нет повторного номера | **Зал** | **Ожидает** |
| Ожидающий черновик «На вынос» | `Заказ №N`¹ | Нет повторного номера | **На вынос** | **Ожидает** |

¹ До первой отправки `N` — **временный номер черновика**, который уже выдаётся сервером в рамках смены. При отправке заказ получает отдельный постоянный `orderNumber`; он может отличаться. Слово «Ожидает» помогает отличить черновик. Полный доступный текст и подсказка карточки должны прямо указывать «Черновик №N», чтобы временный номер не принимали за уже присвоенный постоянный. Если требуется сохранять один и тот же номер до и после отправки, это отдельное изменение серверной нумерации, не входящее в это ТЗ.

## Правила интерфейса

- Порядок внутри карточки: заголовок → при наличии строка с номером под ним → заметный бейдж типа → ниже бейдж статуса → количество позиций, сумма/время и существующий поминутный счётчик отправленного заказа. Бейджи типа и статуса никогда не заменяют друг друга.
- «Зал» и «На вынос» — отдельные заметные цветовые бейджи с различимой подписью; статус сохраняет собственный цвет и подпись. Для кыргызского интерфейса используются соответствующие переводы. Состояние не передаётся одним лишь цветом.
- При переключении типа ожидающего черновика бейдж типа и заголовок меняются сразу после сохранения выбора: «Зал» ↔ «На вынос». Если выбранный стол скрыт при переходе на вынос, карточка показывает номер черновика; при возврате в зал сохранённый стол снова становится заголовком. Статус остаётся «Ожидает».
- При назначении/переносе/снятии стола заголовок меняется по подтверждённому состоянию. Не определять наличие стола по тексту `Без стола`: использовать `tableId` из серверного DTO или надёжную связь с таблицей посещений.
- У старого принятого заказа без публичного `orderNumber` использовать существующую подпись «Номер не присвоен», не придумывать номер. Неизменны действия открытия/удаления карточки, сортировка, состояние выбора, стоимость, время отправки и восстановление после перезагрузки.
- Карточка остаётся читаемой на 1366×768 и 1920×1080, в русском и кыргызском интерфейсах. Допустимо увеличить её высоту; соседние карточки не должны перекрываться, подписи не должны заходить на кнопку удаления, сумму и время.

## Приёмка

1. Все шесть строк матрицы совпадают с отображением; номер заказа под столом не дублируется в заголовке.
2. У обоих типов заказа видны **два** бейджа в указанном порядке: тип, затем статус. У ожидающих переключение типа сразу обновляет бейдж и заголовок, включая сохранённый стол.
3. Для ожидающих показан временный номер черновика; после первой подтверждённой отправки карточка показывает постоянный номер заказа. Потеря ответа и перезапуск не создают ложного постоянного номера.
4. Старые заказы без номера, длинные названия столов, RU/KY, 1366×768 и 1920×1080 отображаются без наложений. Действия карточек и таймер POS-017 работают как прежде.
5. Проверены Desktop QA FAST_FIRST, относящиеся к формату серверного DTO тесты и `pnpm check` на временном профиле.

## Технические ориентиры

Рендер карточек: `apps/pos-desktop/fast-sales.js` (`fastDrawActive`). Стили: `apps/pos-desktop/order-first-cart.css`. Ожидающие карточки получают `cash_drafts.draft_number`; принятые — `orders.orderNumber`. Для точного определения назначенного стола в ответ `activeOrders` добавлен `tableId` (`apps/local-server/src/modules/orders/finance-service.ts`).

## Реализация и проверка

`activeOrders` теперь возвращает `tableId` только для доступного заказа в зале, используя уже проверенное посещение. Новый блок заголовка и два бейджа включены только для FAST_FIRST; карточки TABLE_FIRST/TABLE_QUICK не менялись. Для ожидающего черновика визуально используется `Заказ №N`, а доступное имя и подсказка называют `Черновик №N`.

`pnpm check` — PASS; `pnpm test` — 238 тестов / 40 файлов PASS. Desktop QA `order-first-cart-qa.cjs`, `cash-workspace-qa.cjs` и `fast-sales-qa.cjs` — PASS на временных профилях, включая переключение типа, назначение стола и сценарий кассира. Скриншоты 1366×768 и 1920×1080 проверены. Рабочие профили и реальные смены не менялись.
