# WAITER-UI-002 — Главный экран официанта

Статус: реализовано в Waiter Web 28.10.2026. Визуальный ориентир — два изображения пользователя в задаче WAITER-UI-002. Серверные права и данные остаются источником истины.

## Зафиксированный интерфейс

- После нового входа открывается вкладка «Мои столы»: только активные TABLE-посещения, где текущий официант указан ответственным. Если их нет, показываются пустое состояние и действие «Посмотреть все столы».
- «Все столы» показывает доступные зоны и их столы. Зоны раскрываются; столы представлены только карточками в сетке из трёх колонок. SVG-план зала, режим карты, резерв и нижняя навигация отсутствуют.
- Поиск фильтрует номер/название стола или зоны внутри выбранной вкладки. Статус и права берутся из `GET /waiter/api/v1/tables` Local POS Server, обновление не создаёт локального фиктивного состояния.
- Свободная карточка открывает подтверждаемое действие «Открыть стол» при праве `table.open` и открытой смене. Занятая карточка открывает посещение только при `canViewDetails`; иначе показывает отказ без запроса деталей.
- Header показывает бургер, имя, роль и аватар-заглушку. Боковое меню содержит «Столы», «Меню», «Заказ», «Профиль», «Настройки», «Помощь» и «Выход»; закрывается кнопкой, подложкой и системным «Назад». Бейдж «Заказ» показывает количество локальных непустых черновиков, а не число с референса.
- «Меню» — доступный для чтения каталог Local POS Server. «Заказ» возвращает к последнему открытому посещению при сохранённом доступе либо предлагает выбрать стол. «Настройки» меняют RU/KY, «Помощь» содержит краткую подсказку, «Выход» требует подтверждения.

## Ограничение серверного контракта

`GET /waiter/api/v1/tables` не отдаёт `responsibleWaiter` для посещения, детали которого сотруднику недоступны. Поэтому имя ответственного чужого стола в режиме STRICT не выводится; карточка сообщает, что детали недоступны. В режиме SHARED или при отдельном праве имя отображается, если сервер его вернул. Раскрывать имя только ради дизайна отдельным обходом прав нельзя.

## Проверки

`pnpm run check`, `pnpm run build`, изолированный `node apps/pos-desktop/test/waiter-http-qa.cjs`: вход, вкладки, поиск, открытие стола, пакет, обновление, Sidebar, недоступность сервера и выход. `node apps/pos-desktop/test/service-clients-qa.cjs --waiter-only` прошёл HTTPS-сценарий с RU/KY и повторным PIN-входом. Полный `service-clients-qa.cjs` останавливается позже на устаревшей проверке настольного экрана сотрудников (`details > summary`). Физический Safari/iPhone и Windows не проверялись.
