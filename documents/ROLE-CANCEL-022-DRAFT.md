# ROLE-CANCEL-022 — права кассира и отмена принятых блюд

**Статус:** утверждено пользователем для реализации, 29.10.2026. Область: POS Desktop, Waiter Web, Local POS Server, матрица прав текущего филиала.

## 1. Решения по шаблонам

1. В исходном шаблоне **Waiter** включить `order.correct` для отмены принятого блюда и `order.cancel` для полной отмены заказа либо последней действующей позиции. Официант отменяет только доступный ему открытый TABLE-заказ до расчёта: свой в STRICT, доступный чужой в SHARED. COUNTER, оплаченные и закрытые заказы недоступны. Явное выключение в матрице ролей имеет приоритет над шаблоном.
2. В исходном шаблоне **Cashier** включить `employee.pin.issue`, `employee.pin.reset`, `employee.create`, `employee.edit`, `employee.status.manage`, `employee.password.reset`, `menu.edit`, `menu.stoplist.manage`, `print.queue.view`, `print.settings.manage`, `print.retry_safe`, `print.reprint`, `print.redirect`, `print.manual_handoff`, `print.resolve_no_print`, `print.release_late`, `network.waiter.manage`. Из них `print.queue.view` и `print.retry_safe` уже включены; остальные требуют изменения сервера и/или шаблона. При сохранённом ранее явном правиле роли оно остаётся приоритетным: миграция не должна молча переписать выбор владельца.
3. Для кассира права персонала ограничить сотрудниками ролей **Cashier/Waiter** в своём филиале. Запретить создание Manager/Owner, повышение роли до Manager/Owner, изменение собственной роли/статуса, сброс собственного PIN/пароля и управление правами. Изменение роли другого сотрудника допустимо только между Cashier и Waiter с отзывом действующих сессий. Архивирование и блокировка не удаляют историю. Эти ограничения проверяет сервер, а не только экран.
4. `menu.edit` позволяет кассиру создавать и редактировать категории, блюда, варианты, составы, цены, архивирование и публикацию редакции меню. `menu.stoplist.manage` отдельно разрешает изменение доступности. Публикация влияет только на новые принятые пакеты; исторические цены не меняются.
5. Включённые права печати действуют по текущим ограничениям состояния, ревизии, доступа к заказу, подтверждению риска и обязательной причине. `network.waiter.manage` даёт кассиру управление адресом/сертификатом Waiter Web; после смены адреса требуется обновить QR и проверить подключение телефонов.
6. По последующему решению пользователя кассиру включены `payment.refund.history`, `payment.incident.resolve`, `financial.case.view`; официанту права возвратов и финансовых случаев не выдаются. Сохранённые явные правила матрицы остаются приоритетными.

7. Всем ролям в исходном шаблоне включены `order.correct`, `order.cancel` и `order.custom_item.create`. Последнее добавляет в заказ позицию «Неизвестный товар» с вручную введённой ценой и без кухонной печати. Owner, Manager и Cashier получают `table.manage`, `settings.table_access_mode.manage`, `counter.view`, `counter.batch.submit`, `order.settle.counter`. Waiter не получает управление залом/режимом и работу с COUNTER.
8. Кассиру дополнительно включены `employee.archive.view`, выдача и сброс PIN, создание, редактирование, изменение статуса и восстановление из архива Cashier/Waiter в своём филиале. Просмотр PIN ограничен только официантами. Кассир не управляет Owner/Manager и собственными учётными данными через административный экран. Для владельца включены `shift.open` и `shift.close`.

## 2. Отмена блюда после отправки

- Рядом с каждой действующей принятой позицией Waiter Web и кассы «Заказы сначала» показать кнопку «Отменить». Она отменяет **всё оставшееся количество данного принятого блюда**, включая несколько действующих порций с комментариями. Для частичной отмены оставить существующий отдельный сценарий выбора количества.
- До команды показать название, вариант, отменяемое количество и сумму уменьшения, запросить обязательную причину и подтверждение. Если позиция — последняя действующая в заказе, явно предупредить: заказ будет полностью отменён, стол освободится; требуется `order.cancel` дополнительно к `order.correct`.
- Использовать существующие `corrections/prepare` и `corrections/commit` с `CANCEL_QUANTITY` или `GROUP_CANCEL`, актуальными `orderRevision`/`visitRevision`, `confirmationHash` и `commandId`. Для полной отмены всего заказа предусмотреть отдельное действие `CANCEL_ORDER` с причиной и подтверждением. В Waiter Web разрешить его HTTP-маршрутом только для TABLE и при серверном `order.cancel`; существующий запрет в web adapter снять адресно.
- Успешная корректировка уменьшает серверную сумму и действующее количество, сохраняет исходный Batch/Item, автора и запись Correction. Если действующих позиций не осталось, сервер закрывает заказ как `CANCELLED` и освобождает TABLE. После оплаты обычная отмена запрещена; возврат денег оформляется отдельно.
- Для кухонной позиции создавать в той же транзакции задание печати **«ОТМЕНА»** с блюдом, количеством, вариантом, столом/заказом, причиной и исполнителем. В кассе «Заказы сначала» заменить текущий быстрый `kitchenPrint: DEFERRED` на обычное задание отмены. Успех бизнес-операции означает сохранение задания, а не физическую доставку бумаги: `SENT` подтверждает только принятие spooler. Ошибка/UNKNOWN печати остаётся в очереди с действующими правилами безопасного повтора.
- Если право отозвано, заказ закрыт другим сотрудником, сумма или ревизия изменилась, интерфейс обновляет данные и не показывает локальную отмену как принятую. При потерянном ответе проверять исходную команду; не создавать вторую отмену автоматически.

## 3. Матрица и интерфейс

В «Роли и права» названия и подсказки к спорным правам сделать понятными. Квадрат означает разрешение для всех сотрудников данной роли в текущем филиале; выключение запрещает действие даже при наличии кнопки. Замок означает жёсткий предел роли, который сейчас нельзя изменить в матрице. Для новых разрешений кассира расширить этот предел адресно; для Waiter расширить только `order.cancel` (предел `order.correct` уже разрешён). После изменения роли/права сервер проверяет его на следующей операции.

## 4. Приёмка

Проверить одну/несколько одинаковых позиций из разных пакетов, вариант/комментарий, отмену всего остатка позиции, последнюю позицию, полную отмену заказа, сумму/скидку/сборы, закрытие TABLE, STRICT/SHARED, отзыв права, конкурирующую оплату/коррекцию, повтор команды, потерю ответа и печатное задание. Для кассира проверить создание/редактирование/блокировку Cashier/Waiter, запрет Manager/Owner и самоповышения, PIN/пароль, публикацию меню, стоп-лист, каждое действие печати и настройки Waiter Web. Тестировать только на изолированном профиле; рабочую MANGO не обновлять автоматически. Физическую печать на Windows и телефоны проверять отдельно.
