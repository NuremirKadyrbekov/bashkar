# TABLES-UI-002 — компактные карточки, зоны и быстрый переход к продаже

**Статус:** утверждено пользователем; ближайший этап реализован 24.10.2026. Будущий этап QR/NFC запросов гостей остаётся планом. **Область:** Bashkar POS Desktop, экран «Столы». Документ дополняет `BASHKAR_POS_UI_001_Управление_столами_ТЗ.md`; правила ARCH-001, CORE-001 и AUTH-001 сохраняются.

## 1. Цель и текущая основа

Сделать экран компактнее и удобнее на POS-мониторах, сохранив четыре карточки в строке, крупные сенсорные цели и обзор заказов справа. Desktop получает зоны, столы, время открытия и суммы из Local POS Server, обновляется через WebSocket и проверяет права и смену. На момент согласования карточки занимали 198 px по высоте (175/155 px в компактных режимах), таймер показывал `00:00`, вместо столика выводился символ `▤`, а все активные зоны последовательно удлиняли список. Кнопка быстрой продажи появлялась только при правах `counter.view` и `counter.batch.submit`.

## 2. Изменения ближайшего этапа

### Компоновка и карточки

- Удалить подзаголовок «Выберите стол для создания заказа или управления текущим.» Заголовок «Столы» и действие быстрой продажи расположить в одной верхней строке.
- Немного уменьшить карточки: ориентир — высота около 178–182 px на 1920×1080 и 142–150 px на 1366×768, с уменьшенными внутренними отступами. Сохранять читаемые имя, статус, автор, длительность, пакеты и сумму; не обрезать сумму и доступные сведения о гостях. Четыре карточки в строке при 1366 и 1920 px. Вся доступная карточка остаётся сенсорной целью, фокус видим.
- Для свободного стола заменить `▤` локальным SVG с узнаваемым столом в мягкой псевдо-3D перспективе: столешница, две опоры/ножки, лёгкие мятно-синие градиенты и умеренная тень. SVG хранить в проекте или как кодовый компонент, без сети и внешних шрифтов. Подпись «Готов к приёму гостей» сохраняется. При необходимости ту же иконку использовать для TABLE в правой панели. Декоративную иконку скрыть от screen reader; смысл передаёт текст карточки.
- Светлая тема, пропорция основных колонок 70/30 и общая шапка остаются. При нехватке высоты прокручивается область столов, а не вся страница.

### Длительность посещения

- Показать возраст текущего посещения словами: до часа — `0 мин`, `30 мин`, `59 мин`; с часа — `1 час`, `1 час 1 мин`, `2 часа 30 мин`. Для последующих суток продолжать часы (`24 часа 1 мин`), чтобы длительность не сбрасывалась. RU/KY склонение и переводы должны быть корректными.
- Считать от серверного `openedAt` с существующей поправкой на `serverTime`, округляя вниз до полной минуты; обновлять не реже одного раза в минуту без запроса к серверу на каждую карточку. После перезапуска и переподключения пересчитывать из серверного времени. Будущие/ошибочные отметки не дают отрицательной длительности. Точное время открытия остаётся доступным в подробностях посещения.

### Быстрая продажа

- Показывать заметную бирюзовую кнопку `+ Быстрая продажа` справа от заголовка по образцу референса: высота не менее 48 px, крупная зона нажатия, понятные hover/focus/disabled состояния. Кнопка присутствует в интерфейсе независимо от роли, но при отсутствии прав или закрытой смене недоступна с понятной причиной. Не создавать заказ при одном нажатии: открывается существующий редактор COUNTER; запись создаёт только сервер после подтверждения непустой корзины.
- Не обходить `counter.view`, `counter.batch.submit`, проверку смены и серверную авторизацию. Ошибку отказа показывать, не создавая видимость успешной продажи.

### Вкладки зон и фильтры

- Под строкой фильтров статуса разместить горизонтальные вкладки **всех активных зон филиала** в порядке сервера: «Зал», «VIP», «Терраса» и любые добавленные владельцем зоны. Названия брать только из Local POS Server, без жёстко заданного списка. Если активная зона одна, вкладки можно не показывать.
- По умолчанию выбирать первую активную зону; одновременно показывать карточки только выбранной зоны. Отдельную вкладку «Все зоны» не добавлять, чтобы список вновь не становился длинным. При обновлении данных сохранять выбор по `zoneId`; если зона отключена или удалена, выбирать первую доступную. Пустая зона показывает явное пустое состояние.
- Счётчики «Все», «Свободные», «Занятые» рассчитывать по **выбранной зоне**; выбор статуса сохранять при переключении зон. Поиск ограничить выбранной зоной и текущим фильтром; очистка поиска возвращает карточки выбранной зоны. Вкладки прокручиваются горизонтально при большом числе зон, не сжимая цель нажатия менее 44 px.
- При WebSocket-событии перечитывать серверный снимок и синхронно обновлять вкладки, счётчики и карточки. Не показывать приватные сведения по чужому посещению в STRICT; SHARED и персональные права оставляет за собой сервер.

## 3. Запросы гостей — будущий этап QR/NFC menu

В этой итерации **зафиксировать UX и контракт**, но не показывать вымышленные запросы и не вводить рабочее создание/снятие запроса. Пока Local POS Server не поддерживает их, «Нужно внимание» остаётся недоступным с объяснением. `FREE`/`OCCUPIED` — базовое состояние стола; красная подсветка — дополнительный индикатор только для занятого стола с реальным активным запросом.

Будущий серверный объект `TableServiceRequest` привязан к филиалу, столу и **текущему посещению**. Типы: `REQUEST_BILL` → «Просит счёт» и `CALL_WAITER` → «Вызывает официанта». Минимальные поля: ID, тип, состояние, `created_at`, источник, ревизия и история действий сотрудников. Для обработки предусмотреть `OPEN → ACKNOWLEDGED → RESOLVED`; снятие индикации выполняется только отдельным подтверждённым сервером действием сотрудника, с правами и журналом. Если открыты оба типа, карточка показывает оба; счётчик «Нужно внимание» считает **столы**, а не число запросов. Оплата/закрытие посещения атомарно завершает связанные открытые запросы, чтобы свободный стол не оставался красным. Повторный QR/NFC вызов, идемпотентность `command_id`, защита от подмены филиала/посещения и антиспам-политика определяются при проектировании QR/NFC.

Клиент QR/NFC не должен напрямую менять `table_sessions` или локальную БД. Отдельный будущий шлюз должен аутентично привязать запрос гостя к действующему посещению; Local POS Server проверит источник, состояние стола, права сотрудника при подтверждении, сохранит событие и разошлёт изменение через существующий WebSocket. Детали чужих посещений по-прежнему фильтруются по STRICT/SHARED. Схему, API и миграцию утвердить отдельным ТЗ для QR/NFC; текущая итерация их не создаёт.

## 4. Проверка и критерии приёмки ближайшего этапа

1. На 1366×768 и 1920×1080 экран без боковой панели: четыре компактные карточки в строке, верхняя кнопка заметна, зоны переключаются касанием и клавиатурой, длинного объединённого списка зон нет. Русский и кыргызский тексты не накладываются.
2. Таймер для серверных отметок 30, 60, 61 и 150 минут показывает соответственно `30 мин`, `1 час`, `1 час 1 мин`, `2 часа 30 мин`; после перезапуска значение восстанавливается. Проверить граничное склонение и KY.
3. Переключение зон/статуса и серверное изменение столов обновляют видимые карточки и счётчики без мок-данных. Удаление выбранной зоны даёт безопасный выбор другой.
4. Быстрая продажа открывает существующий COUNTER редактор при действующих правах и смене; пустая корзина не создаёт заказа. При недоступном сервере и отказе в правах успех не показывается.
5. SVG доступен локально без интернета; интерактивные элементы имеют видимый фокус, подписи и удобный размер. Проверки выполнять на одноразовом профиле, не затрагивая MANGO/рабочую смену.

**Результат ближайшего этапа:** изменены Desktop UI и локальный SVG; проверены типы/синтаксис и Electron-снимки на двух размерах. Серверный модуль гостевых запросов — отдельный будущий этап; данный документ сохраняет его план, но не заявляет реализацию.
