# POS-016 — счётчик частичной выдачи

ТЗ и реализация от 27.10.2026. Схема 17, без миграций.

## Требования и поведение

- Заменить галочку выдачи у отправленной позиции счётчиком «Выдано − 3 / 5 +». Числитель — отмеченное количество, знаменатель — оставшееся заказанное количество этой исходной строки пакета.
- «+» отмечает выдачу ровно одной единицы. «−» уменьшает ошибочную отметку на одну. Диапазон от 0 до currentQuantity, на границах соответствующая кнопка отключена.
- Синий фон/контур выдачи отличается от счётчика жёлтой сборки. На coarse pointer кнопки имеют размер 44 px. Полная выдача имеет усиленный синий фон.
- Изменение сохраняется на сервере с сотрудником, временем, revision и неизменным событием. Подсказка счётчика показывает последнего сотрудника/время. Суммы заказа, платежи и задания печати от отметки выдачи не меняются.
- Доступно только с `order.fulfillment.mark` в открытом заказе/смене. Закрытый заказ показывает количество только для чтения. Новая строка другого пакета начинает с 0.
- Отмена уменьшает знаменатель; отображаемое выданное количество ограничивается новым остатком. Исторические события не переписываются. Старую ошибочную отметку «всё выдано» можно исправить кнопкой «−».
- Пока запрос выполняется или результат неизвестен, счётчик этой позиции блокируется. Pending восстанавливает исходную команду; повтор не добавляет ещё одну единицу. Конкурирующая устаревшая команда отклоняется по CAS и вызывает обновление данных.

## Серверный контракт

Существующий `POST /api/v1/orders/:id/fulfillment` принимает ровно одно из двух полей:

- `issuedQuantity`: целое абсолютное количество от 0 до текущего остатка; используется новым UI.
- `issued`: прежнее boolean-поле для совместимости (true — весь остаток, false — ноль).

Обязательные `commandId`, `itemId`, `expectedRevision`, `expectedOrderRevision` сохраняются. Одновременные `issued`/`issuedQuantity` и отсутствие обоих отклоняются. Проверяются права, область доступа, открытый заказ/смена, обе ревизии и границы количества. Чтение/изменение чужой строки не допускается.

Ответ включает `issuedQuantity`, `quantity` (текущий заказанный остаток) и `issued` (выдан весь остаток), а также прежние orderId/itemId/revision. DTO batches.fulfillment дополняется `issuedQuantity`: для положительного события это min(записанное количество, текущий остаток), для `issued=false` — 0. API событий также возвращает issuedQuantity.

Используется прежняя append-only таблица `order_fulfillment_events`. При положительном значении её quantity хранит выданное количество; ноль сохраняется как issued=false с положительным snapshot количества, совместимо с прежним CHECK(quantity>=1). Старые записи/миграции не меняются.

Native сохраняет pending до проверки ответа и для нового запроса сверяет orderId/itemId, revision и точное issuedQuantity. Счётчики других строк и редактирование личного дозаказа сохраняют независимость. При полном расчёте незавершённое восстановление отметки не превращается в новую выдачу.
