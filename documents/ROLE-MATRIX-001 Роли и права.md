# ROLE-MATRIX-001 — Роли и права

**Статус:** реализовано 29.10.2026. **Область:** POS Desktop → Local POS Server → SQLite, только текущий филиал.

## Экран

Раздел «Роли и права» показывает матрицу: строки Owner, Manager, Cashier, Waiter; первый закреплённый столбец — роль, справа горизонтально прокручиваются разрешения, сгруппированные по операциям. У ячейки три состояния: включено, выключено, запрещено серверным пределом роли. Owner показан для справки и не редактируется. Недоступные ячейки не кликабельны. Подписи объясняют права и происхождение текущего состояния. Интерфейс использует светлую тему Bashkar, допускает 1366×768 и 1920×1080, показывает загрузку, ошибки и актуальную редакцию.

## Правила

Только Owner с `employee.permissions.manage` меняет шаблоны Manager, Cashier и Waiter. Изменение одного права требует подтверждения, отправляется как команда с `commandId` и ожидаемой редакцией, записывается в аудит и начинает действовать для всех сотрудников этой роли в текущем филиале при следующей серверной проверке операции. Серверный `roleAllows` остаётся жёсткой верхней границей. Нельзя отключить у Owner управление правами или обойти предметные ограничения операций.

Приоритет: жёсткий предел роли → сохранённое правило роли → индивидуальное исключение сотрудника → исходный шаблон. Таким образом, явное правило в матрице одинаково для всех сотрудников роли. Индивидуальные исключения продолжают действовать только для прав, которые в матрице ещё не изменялись. Изменять индивидуальное исключение поверх явного правила роли сервер запрещает кодом `ROLE_RULE_LOCKED`. Экран объясняет это, чтобы пользователь не путал личные исключения с общими правилами.

Сервер возвращает каталог прав, разрешённость по роли, эффективное значение ролевого шаблона и редакцию. При конфликте редакции клиент перечитывает матрицу. При неопределённом результате клиент не утверждает успех и позволяет проверить состояние. Изменение роли сотрудника сразу переводит его на шаблон новой роли; текущие серверные проверки сессии и предметных ограничений сохраняются.

## Приёмка

Проверить сохранение, конфликт редакции, запрет Manager/Waiter на изменение, жёсткие запреты ролей, применение к двум сотрудникам одной роли, изоляцию филиала и аудит. Рабочую базу MANGO автоматически не мигрировать: новая схема требует отдельного контролируемого обновления без открытой смены.

## Проверки

Изолированный серверный тест проверил действие на двух официантов, приоритет над личным разрешением, блокировку личного изменения, повтор команды, конфликт редакции, запрет жёстко недоступного права, аудит и запрет для Manager. HTTP API тест проверил чтение, сохранение и запрет посторонних полей. Браузерный QA на одноразовом транспорте проверил строки, подтверждение и сохранение, размеры 1366×768 и 1920×1080. Рабочий профиль MANGO не использовался.

## Обновление шаблонов 29.10.2026

Исходные шаблоны и жёсткие пределы ролей расширены по утверждённому [ROLE-CANCEL-022](ROLE-CANCEL-022-DRAFT.md). `order.correct`, `order.cancel`, `order.custom_item.create` доступны всем ролям. `table.manage`, `settings.table_access_mode.manage`, `counter.view`, `counter.batch.submit`, `order.settle.counter` доступны Owner, Manager и Cashier, но запрещены Waiter. Для Cashier доступны управление Cashier/Waiter, меню, стоп-лист, печать, настройки Waiter Web, история возвратов, разрешение платёжного инцидента и просмотр финансового случая. Сохранённые явные решения владельца в матрице имеют приоритет; изменение исходного шаблона не перезаписывает их.

## Шаблон платформы от 02.11.2026

Эффективная матрица ролей филиала «34» в профиле `FRESH-20261102` зафиксирована в [`config/platform-role-template-fresh-20261102.json`](../config/platform-role-template-fresh-20261102.json). Она включает все разрешённые права Owner, Manager, Cashier и Waiter. Источник значений для новых установок — `defaults` и `roleAllows` в `apps/local-server/src/modules/auth/permissions.ts`; снимок служит проверкой полного совпадения при создании нового филиала.

По сравнению с прежними исходными значениями Cashier больше не получает `employee.status.manage`, Owner, Cashier и Waiter получают `table.access_others`, а Owner дополнительно получает `counter.hide` («Скрыть из рабочего списка»). Остальные права уже совпадали с матрицей филиала 34. Индивидуальных исключений сотрудников в этом профиле не было; ролевые правила филиала не копируются как персональные права. При отдельном изменении матрицы в заведении его сохранённые правила остаются локальными для филиала и имеют приоритет над шаблоном платформы.
