# ТЗ: два шаблона публичного меню Bashkar

Статус: согласовано владельцем 02.11.2026; реализовано в локальном коде, выпуск в Cloud и на гостевой сайт ожидает отдельной проверки и развёртывания.

## 1. Цель и границы

Сохранить действующий публичный сайт как шаблон **«Классический»**. Добавить шаблон **«Категории»** по двум приложенным визуальным ориентирам: сначала широкая фотография, затем блок с названием и текстами, далее поиск и крупные карточки категорий; внутри категории — горизонтальные карточки блюд. Переключатель шаблона разместить в существующем редакторе «Публичное меню» Desktop POS. Смена в редакторе до сохранения влияет только на предпросмотр. Существующие QR/NFC-ссылки, филиал, стол, каталог, цены, варианты, наличие и публикация каталога сохраняют свою семантику.

## 2. Проверенная основа проекта

- В `apps/public-menu/dist/app.js` работает один гостевой макет: hero, поиск, фильтры категорий, сетка блюд и диалог вариантов. Гостевой API отдаёт категории и блюда из опубликованной версии каталога.
- `public_menu_design` хранит тему, языки и шесть локализованных текстов; версия защищена `expectedRevision`. Запись доступна Owner через существующий Cloud маршрут. Требуется совместимое расширение этой схемы для шаблона, Wi‑Fi и оформления категорий.
- Логотип и баннер используют медиаслоты `public_logo` и `public_banner` через текущую подписанную загрузку в Bunny. Фото блюд используют тот же механизм. Для фоновых фото категорий нужны новые разрешённые слоты, проверка существования категории, привязка к филиалу и очистка/недоступность после удаления категории.
- Публичный ответ содержит URL изображений Bunny и кэшируется до 30 секунд. Медиа сейчас публикуются сразу после успешной загрузки, отдельно от кнопки сохранения текстовых настроек.

## 3. Данные и совместимость

Расширить существующую конфигурацию оформления, не создавая второй независимый редактор или каталог:

- `template`: идентификатор `classic` или `categories`; для старых записей и при отсутствии поля — `classic`.
- `wifi`: SSID (название сети) и пароль. Пустые значения скрывают блок или соответствующую строку. Эти значения относятся к филиалу, общие для обоих шаблонов. Поскольку гостевая страница публична, указанный пароль будет виден всем посетителям с ссылкой. UI должен об этом прямо сообщать перед сохранением.
- `categoryPresentation`: словарь по стабильному ID категории. Для каждой категории — редактируемый заголовок по RU/KY/EN и ссылка на текущий опубликованный Bunny-ресурс; пустой заголовок использует перевод названия категории из каталога, затем его основное название. Название категории в самом каталоге не меняется.
- Поля нового оформления проверяются на сервере по типу, длине, доступным языкам и принадлежности категории опубликованному каталогу. Сохранение атомарно с ревизией оформления. Старый клиент и старые данные продолжают показывать `classic`.
- Пароль Wi‑Fi не записывать в журналы, телеметрию или URL. Он передаётся только по HTTPS и включается в гостевой ответ лишь когда задан. Доступ на запись — существующая роль Owner. Не показывать пароль в предпросмотре публичного сайта случайным пользователям локального POS без прав Owner.

## 4. Редактор владельца

- В существующей странице добавить карточку **«Шаблон сайта»** с двумя вариантами, миниатюрами и описанием. Выбор переключает локальный предпросмотр. Сохранение и публикация идут через расширенный существующий `publicMenuDesignSet` с проверкой ревизии.
- Сохранить действующие поля темы, языков, шести текстов, логотипа, баннера и статуса сайта. Текущие тексты использовать в обоих шаблонах: для нового макета баннерная фотография идёт первой, затем заголовок, описание и нижняя строка. Метку показывать только если она заполнена.
- Добавить блок **«Wi‑Fi для гостей»**: SSID и пароль, возможность показать/скрыть пароль при вводе, явное пояснение о публичности. В предпросмотре отображать Wi‑Fi так же, как на выбранном гостевом шаблоне.
- Добавить блок **«Оформление категорий»** со списком реально опубликованных категорий. Для каждой: локализованный заголовок, текущая миниатюра, загрузка/замена/удаление фона. Предпросмотр обновляется после успешной загрузки. Если категория не опубликована, не создавать для неё публичную карточку.
- Кнопка «Отменить правки» возвращает сохранённые шаблон, тексты, Wi‑Fi и заголовки. По текущей архитектуре загрузка/удаление изображений применяется сразу; редактор должен явно показывать это до операции. Если требуется единая транзакция «всё только после Сохранить», это отдельная backend-доработка со staging media.
- Ошибка Cloud не стирает черновик. На уходе со страницы предупреждать о несохранённых текстовых настройках. Дата и статус публикации берутся только из ответа сервера.

## 5. Гостевой сайт: шаблон «Классический»

Сохранить действующую структуру hero → поиск и фильтры категорий → сетка блюд → диалог вариантов. Добавить компактный блок Wi‑Fi после вступительного блока, визуально согласованный с текущей темой. Не менять существующие URL и поведение заказа (гостевой заказ сейчас не предусмотрен).

## 6. Гостевой сайт: шаблон «Категории»

- Первый экран: широкая фотография баннера, поверх неё переключатель языка; затем текстовый блок с названием филиала/заголовком, описанием и дополнительными строками. Не копировать дословно чужой дизайн или его демо-данные.
- После вступления — блок Wi‑Fi, если заполнен. Пароль показывать разборчиво; добавить доступное копирование SSID/пароля по нажатию. Не пытаться автоматически подключать устройство к сети.
- Ниже — поиск блюд и вертикальный список крупных карточек опубликованных категорий. Карточка показывает заголовок с fallback, Bunny-фото под затемнением для читаемости; без фото — аккуратный цветовой фон. Использовать порядок категорий опубликованного каталога.
- Выбор категории открывает представление этой категории в рамках существующего адреса филиала/стола: заголовок, кнопка «Назад к категориям», поиск и горизонтальные карточки блюд с фото/placeholder слева, названием, описанием и ценой справа. Варианты, дополнения и матричные цены остаются в существующем диалоге блюда. Недоступность блюда показывать по текущим правилам публичного сайта.
- Адрес категории делать как состояние URL (например hash или query, окончательный формат определить после проверки текущих QR-маршрутов), чтобы работали «Назад», обновление страницы и прямая ссылка. Некорректный/удалённый ID категории возвращает на список категорий. QR-ссылка на филиал/стол остаётся прежней.
- Поиск на стартовой странице ищет по названию и описанию всех опубликованных блюд на активном языке и fallback; результаты открывают соответствующую категорию/блюдо. На странице категории поиск ограничен этой категорией. Пустой запрос возвращает список категорий или все блюда категории. Пустая выдача получает понятное сообщение.
- Смена языка сохраняет текущую категорию и запрос. На узких экранах макет становится одноколоночным без горизонтальной прокрутки.

## 7. Изображения и скорость

- Использовать текущую подписанную загрузку в Bunny, добавив стабильные слоты категории на основе ID и проверку принадлежности филиалу. Не давать произвольный `itemId` без серверной проверки.
- Ограничить форматы JPEG/PNG/WebP и 10 МБ на сервере; в Desktop перед отправкой уменьшать фон категории до разумного максимума (предлагается 1600×1000) и сжимать. Оптимальный формат/качество уточнить по возможностям текущего Electron/Bunny-контура. Изображение должно сохранять читаемость текста на карточке.
- Использовать существующие неизменяемые URL ресурсов Bunny; для карточек категорий и блюд — lazy loading, для верхнего баннера — приоритетная загрузка. Указать размеры/aspect-ratio, чтобы страница не прыгала. Кэширование гостевого JSON до 30 секунд учитывать в UI после публикации; не обещать мгновенное появление на уже открытом устройстве гостя.
- Категории и блюда уже приходят одним ответом гостевого API: переключение категорий и поиск выполнять в браузере без отдельного запроса на каждую категорию. Если каталог окажется очень большим, отдельно измерить размер ответа и время загрузки перед введением пагинации.

## 8. Порядок реализации и выпуска

1. Миграция и серверная валидация новых полей, медиаслотов категорий, владельца и филиала. Проверить обратную совместимость старого клиента.
2. Расширить гостевую проекцию и два шаблона сайта, сохранив `classic` по умолчанию. Добавить URL-состояние категории, поиск и горизонтальные карточки.
3. Расширить редактор, предпросмотр, тексты Wi‑Fi и категории. Для точного предпросмотра переиспользовать общий рендер/стили гостевого сайта либо сделать изолированный preview-режим гостевой страницы с передачей несохранённого черновика без публикации; не отправлять черновик в публичный API.
4. Проверить RU/KY/EN, fallback, вариантные цены, пустые категории/фото, запрет чужого филиала, конфликты ревизий, медленные/ошибочные загрузки, мобильные размеры и клавиатурное управление.
5. Выпустить сначала совместимый backend и гостевой сайт, затем обновлённый Desktop. Проверить на реальном тестовом филиале и Bunny; только после этого переключать рабочий филиал.

## 9. Приёмка

Существующий филиал без новых настроек продолжает видеть текущий шаблон. Владелец переключает два шаблона в одном редакторе и видит черновик в предпросмотре без изменения гостевого сайта. После подтверждённого сохранения новый шаблон открывается по прежнему QR/NFC URL. Wi‑Fi корректно виден в обоих шаблонах. Каждая опубликованная категория имеет собственную страницу и фон, блюда открывают существующие варианты и цены. Поиск, язык, Back/Forward, пустые состояния и мобильный экран работают. Ошибки Cloud/Bunny не создают ложного сообщения об успехе и не теряют текстовый черновик.

## 10. Подтверждённые решения

1. Wi‑Fi показывать гостям открытым текстом в обоих шаблонах; поля необязательные.
2. Заголовки категорий редактировать отдельно от каталога на RU/KY/EN; пустой перевод наследует название категории.
3. Фон категории публиковать сразу после загрузки в Bunny по текущему механизму. Для полностью отложенной публикации медиа потребуется отдельный staging.
4. Поиск на стартовом экране искать по всем блюдам, внутри категории — только в ней.
