# WAITER-ACCEPTED-ITEM-UI-024 — строка принятого блюда и счётчик выдачи

**Статус:** реализовано 29.10.2026 по запросу пользователя. Область: только принятые позиции экрана активного стола Waiter Web.

## Поведение и компоновка

1. Слева в строке: название, действующее количество × цена, вариант/комментарий, затем итоговая сумма позиции. Сумма больше не занимает отдельную правую колонку.
2. Справа в верхней части той же строки: кнопка `•••`, затем счётчик `− / выдано из действующего / +`. Порядок сохраняется на ширине 320 px; кнопки остаются удобными для касания, длинные названия переносятся.
3. Счётчик меняет только факт выдачи через существующий `order.fulfillment.mark` и серверные ревизии. После успешного ответа обновляются только число, доступность кнопок и локальное состояние строки. Страница и прокрутка не пересоздаются; стоимость не меняется.
4. Во время запроса обе кнопки счётчика блокируются. При неопределённом результате не показывать новое число как подтверждённое; оставить восстановление команды и показать существующее уведомление. При конфликте перечитать актуальные данные, сохранив позицию прокрутки.
5. Проверить внешний вид на 320/390 px, отсутствие горизонтальной прокрутки, последовательные нажатия счётчика, неизменность суммы и положения прокрутки, обработку ошибок и существующие действия `•••`.

## Результат

- Сумма находится под названием, количеством и характеристиками блюда. Справа стоят `•••`, затем счётчик выдачи.
- Успешная выдача меняет только состояние текущей строки по подтверждённому ответу `order.fulfillment.mark`, без повторного вызова `visit(id)` и сброса прокрутки. Во время запроса обе кнопки заблокированы; при неизвестном результате счётчик не принимает новое значение и остаётся механизм проверки команды.
- `pnpm run check` и изолированный `waiter-http-qa` прошли. QA проверяет 320/390 px, геометрию элементов, отсутствие горизонтальной прокрутки, сохранение DOM-строки и `scrollY` после выдачи, последовательные `+ / −`, комментарий и отмену.
