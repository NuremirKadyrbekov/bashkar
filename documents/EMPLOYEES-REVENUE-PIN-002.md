# EMPLOYEES-REVENUE-PIN-002 — PIN, выручка и сообщения экрана «Сотрудники»

Дата: 28.10.2026. Статус: согласованное правило MVP и техническое задание.

## Решения и границы

- Для TABLE вся оплаченная сумма относится **последнему ответственному официанту на момент оплаты**. Ответственный берётся из неизменяемого снимка Settlement, а не из текущей карточки стола. Если ответственного не было, сумма относится сотруднику, зарегистрировавшему оплату.
- Для COUNTER сумма относится сотруднику, зарегистрировавшему оплату. При смешанной оплате учитываются отдельные Payment без повторного суммирования Settlement.
- Выручка за календарный день филиала (Asia/Bishkek) = оплаты, зарегистрированные в этот день, минус возвраты, зарегистрированные в этот день. Возврат относится тому же сотруднику, которому была зачтена исходная оплата. Поэтому дневное значение может быть отрицательным. Нулевой расчёт не создаёт Payment и не увеличивает выручку.
- Это **операционный показатель распределения**, а не денежная сумма, лично полученная официантом. Суммы сотрудников не должны дублироваться. Показатель доступен только при `employee.edit` и `sales.view_24h`.
- **Будущая модель:** распределять выручку по подтверждённым Order Batch и их исполнителям с учётом отмен, скидок, сервисных сборов и возвратов. Это отдельное проектирование финансовой атрибуции; текущая формула не должна выдаваться за пакетную.

## Экран

1. В правой панели каждого сотрудника после блока четырёх операционных счётчиков показать «Выручка за сегодня» в сомах, с пояснением основания: обслуженные заказы для TABLE, зарегистрированные оплаты для COUNTER. Если права просмотра денег нет, показать «Нет доступа» без суммы. При недоступности сервера показать ошибку, не фиктивный ноль.
2. После создания CASHIER/WAITER показать полученный из `employeeCreate` четырёхзначный `temporaryPin` (включая ведущие нули) и отдельно временный пароль. MANAGER получает только пароль. PIN не генерируется в Desktop.
3. В основных данных карточки сотрудника сразу после телефона показать поле «PIN-код». Для сотрудника с PIN исходное значение — `••••`. Кнопка «Показать» вызывает серверный `pinReveal`; полученный код виден 3 секунды, затем вновь `••••`. Повторное нажатие во время показа скрывает код сразу. При выборе другого сотрудника, закрытии карточки, навигации, выходе и скрытии окна код очищается. Для сотрудника без PIN показать «Не выдан»; для приостановленного не предлагать раскрытие. PIN никогда не загружается вместе со списком/карточкой.
4. Секреты создания показываются только в первом успешном ответе. При `secretAlreadyIssued` нельзя выдавать новый PIN без отдельной команды reset. PIN текущего сотрудника раскрывается отдельно через аудируемый `pinReveal` при праве `employee.pin.view` и разрешённой цели согласно уточнённому AUTH-002. Секреты не записываются в логи, уведомления, кэш или clipboard.
5. Успех создания, изменения, сброса пароля/PIN, статуса и прав показывать общим Bashkar toast. Убирать старое постоянное сообщение `#status` при успехе. Ошибки и неизвестный результат операции должны быть заметны и не трактоваться как успех; серверные ошибки остаются в существующем механизме обработки.

## Приёмка

- TABLE с переназначением до оплаты целиком зачисляется ответственному из Settlement на момент оплаты; COUNTER — исполнителю оплаты. Другой филиал и другой день исключаются.
- Смешанная оплата, возврат в тот же или следующий день, нулевой расчёт, отсутствие официанта, права доступа и архивный сотрудник обработаны без двойного счёта.
- Создание CASHIER/WAITER показывает PIN с ведущим нулём и пароль один раз; MANAGER — только пароль; повтор команды не раскрывает секреты.
- Карточка активного сотрудника показывает маску, раскрывает код только по нажатию на 3 секунды и скрывает раньше при смене сотрудника, карточки или окна. Owner/Manager без права, Cashier вне своего scope, приостановленный или архивный сотрудник не получают PIN; каждое серверное раскрытие аудируется.
- Фильтры и выбор сотрудника сохраняются, уведомления используют общий стиль, экран проверен на 1366×768 и 1920×1080.
