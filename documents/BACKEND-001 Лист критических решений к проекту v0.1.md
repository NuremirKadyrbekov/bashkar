## III. Что **уже** закреплено и не требует повторного выбора

- Local-First, один Local POS Server/SQLite на филиал MVP; Supabase и Telegram не блокируют локальные продажи.
- TABLE и COUNTER — только два типа, COUNTER без физического стола.
- Роли OWNER/MANAGER/CASHIER/WAITER, локальный логин+пароль, без PIN и доверенных устройств.
- `STRICT/SHARED` для TABLE, автор каждой отправки неизменен; передача ответственности Post-MVP.
- Один действительный полный Settlement, ZERO_SETTLED без Payment, обычных частичных оплат нет.
- Фиксированная скидка; сборы только TABLE и считаются независимо от единой базы после скидки.
- Изменение принятых пакетов — только отдельными корректировками; все финансовые первичные записи сохраняются.
- Только Kitchen/Customer Jobs; кухня печатает только товары с kitchen-print; UNKNOWN не повторяется автоматически.
- Закрытие смены блокируется активными TABLE/COUNTER и известными неурегулированными денежными инцидентами.
- Исходный отчёт закрытой смены не переписывается; нет автоматического создания пустой БД при аварии.
