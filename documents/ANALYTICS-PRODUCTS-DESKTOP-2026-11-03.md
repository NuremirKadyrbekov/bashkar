# Продажи блюд в Desktop POS

Экран владельца открывается из сайдбара и читает локальный API `/api/v1/analytics/products`. В отсутствие интернета доступны локальные продажи и рейтинг текущего филиала. API и навигация допускают только роль `OWNER`; кассиру и другим ролям экран не показывается.

Период: сегодня, 7 дней, 30 дней или выбранные даты, не более 366 дней. Локальная календарная дата определяется по `Asia/Bishkek`, как в существующем обзоре. На экране только число проданных единиц и топ-10 по количеству. Пустой период даёт ноль и пустое состояние.

Источник: запечатанные `PAID`-расчёты, принятые партии, позиции и остатки `order_item_portions` после исправлений до расчёта. Название сохраняется из снимка позиции; категория находится в версии меню партии. Один товар, продававшийся в разных исторических категориях, представлен отдельными строками по категориям. Произвольная сумма без ID товара в рейтинг не входит. Возврат денег не вычитает позиции.

Фоновая синхронизация передаёт поштучные факты `PRODUCT` через уже подписанную операцию `analyticsBatch`; курсор следует порядку запечатанных расчётов и позиции внутри расчёта. После сбоя курсор не сдвигается, отправка повторяется, а Cloud проверяет хэш и идемпотентность. После обновления сервера до схемы 25 ранее оплаченные позиции передаются обратной загрузкой. Cloud сохраняет факты в `analytics_product_facts`, доступной только `service_role`. Отдельный веб-экран и RPC чтения агрегата пока не добавлены.

Для реальной Cloud-синхронизации требуется применить `supabase/migrations/20261103000100_analytics_overview.sql`, затем `supabase/migrations/20261103000200_analytics_products.sql`, развернуть обновлённую функцию `menu-sync` и обновить локальный сервер. Код этого изменения сам не выполняет развёртывание. Миграция локальной схемы 25 выполняется при штатном обновлении сервера без открытой смены.
