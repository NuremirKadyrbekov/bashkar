# POS-CASH-UX-003 — быстрое добавление, варианты и компактная корзина

Дата: 25.10.2026. **Статус: реализовано по подтверждённому ТЗ.** Уточняет реализованный POS-CASH-UX-002; единая «Касса», TABLE/COUNTER, общий номер смены, права, смена и серверные суммы сохраняются.

## 1. Референсы и исходное состояние до этапа

Просмотрены `IMG_9369.HEIC` (диалог «Чай»: кнопки размеров/молока, цена, подтверждение) и присланный PNG (строка блюда: название, цена × количество, сумма, количество и действия). Из референсов брать структуру; использовать светлую мятную тему Bashkar. Оранжевое выделение выбора и ярко-жёлтая кнопка комментария заменяются спокойными фирменными акцентами.

Сейчас `fastAddItem` всегда вызывает общий диалог с select/checkbox, даже для простой позиции. В корзине показана заглушка блюда, комментарий без префикса, ⋯ доступно для каждой позиции. Есть существующие `quote`, комментарий строки и общий `toast`. Новую бизнес-логику цен/создания заказа не вводить.

Фразу пользователя про обычное блюдо трактуем как **«не открывать окно, а сразу добавлять в корзину»**.

## 2. Простое блюдо — одно нажатие

- Если у позиции нет размеров и групп выбора, нажатие на карточку или `+` добавляет одну порцию **без диалога**. Фиксированный SET без пользовательского выбора также может добавляться сразу после существующей проверки компонентов. Наличие единственной доступной опции в группе не считается разрешением игнорировать настроенные правила выбора.
- Если в корзине уже есть идентичная строка с тем же товаром, вариантом, модификаторами и пустым комментарием — увеличить её количество. Строку с отдельным комментарием не объединять с новым добавлением без комментария. Не превышать действующие ограничения количества/составов SET.
- Добавление — изменение неподтверждённой корзины, не создание заказа. Проверить доступность и актуальную сумму через существующий server `quote`; применять результат к актуальному состоянию корзины. Быстрые повторные нажатия не должны терять количество или подставлять устаревший расчёт.
- При закрытой смене сначала действует существующий одношаговый PIN/личный пароль по роли; после успешного открытия простая позиция добавляется без промежуточного окна. При отказе/отмене/недоступном локальном сервере не показывать ложный успех.

## 3. Блюдо с размерами/вариантами — диалог по фото

- Заголовок — название блюда; под ним короткое «Выберите вариант». Размеры и опции групп показывать крупными кнопками/плитками с переносом, вместо выпадающих списков.
- Для одиночного выбора — radio-поведение; для ADDITIVE-групп с несколькими разрешёнными опциями — toggle-поведение с соблюдением min/max. Для MATRIX — ровно один выбор в каждой группе и **полная конечная цена сочетания**, без прибавления вымышленных доплат. Недоступные размеры/модификаторы/сочетания видимы как недоступные и не выбираются.
- Выбранная плитка имеет мятный фон, чёткую рамку и видимый признак выбора. Порядок и названия групп берутся из серверного меню.
- Внизу — заметная **цена текущего выбора**, «Отмена» и основная кнопка **«Добавить · … сом»**. При изменении существующей строки — «Применить · … сом». Показывать цену именно блюда/количества, отдельно от сборов и итогов всего заказа. Пока выбор неполный или актуальный расчёт не получен, подтверждение недоступно.
- Новый товар начинается с количества 1; редактирование сохраняет текущее количество и комментарий. До нажатия «Добавить/Применить» исходная корзина не меняется; отмена, Esc, крестик и фон отменяют только этот выбор. Составы SET и существующие правила доступности/упаковки не обходить.
- Диалог удобен для сенсора и клавиатуры, имеет ограниченную ширину и высоту; при длинном меню прокручивается содержимое, подтверждение остаётся доступным. Не затронуть поведение прежнего редактора TABLE/COUNTER.

## 4. Строка блюда в «Текущем заказе»

Перестроить карточку по иерархии присланного PNG: название; выбранный размер/варианты; цена единицы × количество; сумма строки; компактный блок `−  количество  +`; действия. Убрать нынешнюю декоративную заглушку блюда, чтобы освободить место. На узкой правой колонке данные размещаются в два/три ряда без горизонтального скролла и наложений. Длинное название переносится, суммы не обрезаются. Границы тонкие, фон белый, скругление мягкое. Сумма строки соответствует ценовому снимку текущего server `quote`, итог заказа учитывает серверные скидки/сборы.

- **⋯ вместо стрелки:** показывать только у товара с размерами/группами выбора. Нажатие открывает диалог раздела 3 с уже выбранными значениями. У обычной одиночной позиции без выбора **⋯ скрыто**. Кнопка не смешивает изменение варианта с комментарием.
- **Комментарий:** отдельная небольшая SVG-иконка контура речевого облака, приглушённая по цвету, без жёлтой плашки/emoji. Визуальный размер около 18–20 px, зона нажатия не меньше 44×44 px. Доступна и простой позиции, и товару с вариантами.
- Нажатие открывает отдельный диалог с названием блюда, textarea и кнопкой «Сохранить комментарий». Предзаполнить текущим значением, сохранять в существующий `line.comment`; лимит — 300 Unicode-символов по серверному контракту, нормализация NFC/переносов и запрет управляющих символов. Пустое значение удаляет комментарий. Отмена не меняет строку.
- Под названием/вариантами показывать **«Комментарий: …»** с полным текстом и корректным переносом; префикс — только в представлении, в API сохраняется исходный текст без добавленного слова. При пустом комментарии строку не показывать. Комментарии не теряются при смене размера, изменении количества, фильтрации и обновлении данных.
- Кнопка удаления `×` относится только к локальной строке корзины. Принятые сервером позиции отменяются существующим подтверждённым сценарием, не удаляются из принятого заказа локально.
- Время из PNG не подменять произвольным временем заказа/посещения: сейчас черновик не хранит время добавления отдельной строки. В этом этапе акцент референса воспроизводится остальными полями; колонку «Время» для строки без реального источника не добавлять. Время активных заказов и завершённых продаж сохраняется.

## 5. Единые сообщения о действиях

На затрагиваемых экранах использовать тот же **`toast(success | warning | error, text)`**, что в настройках POS: справа, мягкий зелёный/янтарный/красный цвет, автоматическое исчезновение через **1,5 с**, общая иконография и анимация по UI-MESSAGES-001. Не создавать второй компонент сообщений.

По последующему уточнению пользователя добавление товара в корзину — без уведомления, как для простого блюда, так и после выбора варианта. Для обычных `+`/`−` также достаточно обновления строки/суммы. Подтверждения «Комментарий сохранён», «Скидка применена» и подтверждённое сервером принятие/оплата заказа используют общий toast. Ошибка открытия/сохранения/расчёта не оставляет сообщение прежнего успеха. Ошибка ввода также остаётся около поля до исправления; неизвестный результат команды, потеря сервера и восстановление остаются устойчиво видимыми штатным механизмом.

## 6. Исправление окна скидки

Подогнать размеры самого диалога под встроенную цифровую клавиатуру: ориентир ширины **340–380 px**, `box-sizing:border-box`, одинаковые поля по краям, компактная шапка и дисплей суммы. Сетка клавиш 3 колонки, клавиши не меньше 48 px по высоте, кнопки очистки/удаления и «Применить скидку» целиком внутри диалога.

Учесть максимальную высоту по доступному viewport, системную экранную клавиатуру, фокус и изменение высоты окна. Не показывать две конкурирующие цифровые клавиатуры; физический ввод цифр/разделителя/Backspace остаётся доступным. На 1366×768 и 1920×1080 подтверждение видно без обрезания и горизонтального скролла. Не расширять этим правилом остальные финансовые диалоги. Существующие пределы скидки, серверные суммы и проверка права сохраняются.

## 7. Уплотнение рабочей области

- **Активные заказы:** уменьшить высоту/внутренние отступы ориентировочно на 10–15%, сохранить крупное имя стола/«На вынос», номер заказа, позиции, сумму и время. Типы TABLE/COUNTER по-прежнему различаются подписью и цветом; UUID не возвращать.
- **Последние продажи:** сократить вертикальные отступы и пустое место примерно на 15–20%; номер заказа, тип/стол, время завершения и итог оставить читаемыми. Убрать дублирование одного и того же номера, если он сейчас выводится дважды. Вся строка остаётся доступной для открытия деталей, зона нажатия — не меньше 44 px.
- **Отступ между активными заказами и каталогом:** уменьшить до визуально спокойных **8–10 px**, не допускать слипания рамок. Проверить собственные margin/padding блоков, а не только flex gap.

## 8. Категории в две строки, без «Все категории»

- Убрать видимую категорию **«Все категории»**. Сейчас не добавлять пустую или фиктивную «Популярное» вместо неё.
- При первом открытии выбрать первую действующую непустую категорию в серверном порядке. При обновлении сохранить выбранную, если она ещё действительна; при её исчезновении выбрать следующую доступную. Для отсутствующего каталога — честное пустое состояние.
- Показать кнопки категорий **двумя рядами** над блюдами; длинные названия могут занимать две текстовые строки внутри кнопки. Кнопки имеют единые размеры и читаемую выбранную рамку. Если категорий больше вместимости двух рядов, использовать горизонтальное перемещение сетки без увеличения её высоты до длинного списка. Все категории должны оставаться достижимыми сенсором и клавиатурой.
- Поиск сохраняет текущую семантику поиска внутри выбранной категории. Категории, поиск, диалоги и серверные обновления не очищают корзину.

## 9. Будущая «Популярное» — только план

Отдельно записана [POS-POPULAR-001-DRAFT.md](POS-POPULAR-001-DRAFT.md): после накопления **10–15 реальных завершённых продаж** предусмотреть категорию «Популярное» на месте бывшей «Все категории», с ранжированием блюд по фактическим продажам по убыванию. **В этом этапе статистику и категорию не реализовывать.** Не использовать статические списки или неподтверждённые корзины для имитации популярности. Перед будущей реализацией согласовать точный порог, период и обработку возвратов.

## 10. Критерии приёмки

1. Простая позиция добавляется без модального окна; повторные нажатия сохраняют количество. Закрытая смена вызывает штатную авторизацию, отмена ничего не добавляет.
2. Варианты/размеры выбираются плитками по HEIC, в том числе MATRIX, ADDITIVE, обязательные/необязательные группы, недоступные сочетания и SET. Цена соответствует серверу, отмена не меняет корзину.
3. ⋯ показывается только при наличии выбора и сохраняет количество/комментарий. Отдельный комментарий работает для любого блюда, имеет нужный префикс в строке, редактируется/удаляется без изменения состава и не теряется при обновлениях. Проверить длинный текст, RU/KY и лимит 300 символов.
4. Встроенная клавиатура скидки и кнопка применения помещаются на двух целевых разрешениях; неверная скидка сохраняет прежний итог, успешное применение использует общий toast.
5. Компактные активные заказы/последние продажи сохраняют все перечисленные данные, открывают правильные детали; время берётся из реального источника. Отступы и категории в два ряда проверены визуально; «Все категории» и фиктивной «Популярное» нет.
6. `pnpm check`, подходящие серверные проверки при изменении контрактов и Electron-сценарии на одноразовом профиле. Обязательны 1366×768/1920×1080, мышь/клавиатура и проверка размеров сенсорных зон. Рабочий MANGO, его смена и база не используются для экспериментов. Windows/физический сенсор отмечаются отдельно, если не проверены.
