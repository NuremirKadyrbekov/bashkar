# POS-014 — снимок черновика и проверка меню перед отправкой

Реализовано 27.10.2026 для FAST_FIRST («Заказы сначала»). Схема остаётся 17.

## Поведение

При добавлении/явном изменении выбора блюда черновик сохраняет в `preview[lineId]` название, цену единицы, текст выбранных вариантов/состава, ключ выбора и признаки принятых пользователем условий. Снимок сохраняется в защищённом native state и существующем серверном cash draft. Количество/комментарий остаются в самой строке. Изменение количества или другой позиции не подтверждает новую цену старой строки автоматически.

Пересчёт выполняется Local POS Server по актуальному меню. Переименование категории/блюда, порядок и другие изменения, не затрагивающие выбранные условия, не блокируют отправку. UI продолжает показывать сохранённое название черновика; принятый пакет получает актуальный серверный снимок.

Изменение цены единицы, выбранных условий или состава SET сравнивается с preview. В корзине показано предупреждение; при отправке открывается окно с изменениями и итогом. Подтверждение сохраняет новую baseline и отправляет; отмена сохраняет прежний снимок/черновик. Повторная серверная проверка перед commit защищает от изменений, произошедших во время окна. Для старого черновика без полного preview при смене редакции требуется проверка актуальных условий; отсутствующий исторический снимок не выдумывается.

Недоступная позиция сохраняет название/цену из preview и получает предупреждение. Отправка запрещена до исправления. Строки можно удалять по одной, даже если оставшиеся также недоступны. Снимок не разрешает продажу по старой цене или обход стоп-листа. Уже принятые позиции/расчёты не пересчитываются по новому меню.

## Исправление первой отправки в зал

Ранее публикация категории меняла revision всего меню. Корзина пересчитывалась по новой revision, а исходный серверный cash draft оставался на старой. После открытия посещения обновлялся только локальный visit draft, и `assertCurrentCashDraft` отклонял `batchPrepare` с `DRAFT_REVISION_CONFLICT`.

Теперь до открытия посещения сохраняется актуальный локальный/серверный черновик. При уже открытом пустом посещении обновляется связанный исходный серверный черновик с тем же draft ID, с проверкой `workspace.serverRevision` и CAS. Другой серверный вариант не перезаписывается. Локальный источник очищается только после успешного `batchSubmit`; неизвестный результат остаётся в существующем pending/replay. Новое посещение для восстановления не создаётся.

## Проверки и файлы

- `cash-items.js`: снимок/сравнение условий, маркировка недоступности, окно проверки, сохранение baseline при изменении количества/комментария.
- `cash-workspace.js`: сохранение preview и согласование исходного черновика при первой отправке/восстановлении.
- `draft-store.cjs`: ограниченная сериализация строковых полей snapshot, общий лимит 2 MiB сохранён.
- `fast-sales.js`, `order-first-cart.js/.css`: показ снимка, серверный пересчёт и подтверждение перед отправкой.
- `pnpm run check` PASS; `pnpm test`: 223 теста / 37 файлов PASS.
- Electron `draft-menu-review-qa`, `order-first-cart-qa`, `fast-sales-qa`, `table-quick-sale-qa` PASS.
- Новый прогон: `pnpm run test:draft-menu-review-desktop`; артефакты `artifacts/draft-menu-review-qa/price-review.png`, `composition-review.png`, `unavailable.png`.

Проверки использовали только одноразовые базы/профили. Миграции и рабочие базы не менялись; физическая печать и Windows этим прогоном не проверялись.
